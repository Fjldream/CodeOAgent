# KF 开发助手 M1 启动与试点

本服务把 KF 普通开发人员的个人方案和对话接入开发中心、原生二维页面编辑器及计算工程的周期性脚本。KF 登录态由 Center 校验。个人清单、消息和证据保存在运行助手的主机上。一个方案可以有多段对话。

<!-- modified by jinlong.feng at 2026-11-20 KF开发助手工程上下文与证据 -->
## 本机工程联调版 · 2026-11-20

本轮交付包为 `KF-Development-Assistant-Engineering-20261120.zip`，包含助手服务、前端源码补丁、已编译页面、计算模板和验收记录。与 M1 使用相同的安装位置和个人库，升级前备份原目录，前后端按同一批切换。已有个人方案可继续使用。当前数据模式为单主机 SQLite。

在有权限的工程打开浮窗，选择个人方案，展开“工程工具”。可查操作步骤、当前工程的对象、部署和进程；在二维控件或计算脚本可“追踪上游”或“反查本方案”。反查跨同一方案的各段对话，每次最多复核 16 个可见对象。数采工程还可选“读取实时点值”，选择有权的 App 和完整点名，只订阅一个点，返回其值、质量和源时间。网关需要转发同源 WebSocket 路径 `/ws`。二维和 3D 保持原有的新标签打开方式。脚本编辑器中的“静态检查当前脚本”会把当前正文发送到本机助手做语法及宿主检查，正文不随此检查入库或发送给模型。一般配置查询仅发送当前标签页的文本指纹。选“可复制脚本示例”能取得与当前宿主匹配的模板，点正文后可直接复制。

本轮 OpenCode 使用本机模型协议测试端点验证会话和 MCP，默认入口保持模型关闭。部署方配置云端模型时须另行确定可发送的问题和字段。外部模型只收到匹配本轮入口的受限工具和查询投影。完整 KF 脚本、原始点位和实例清单由本机读取。关联数据和未证实项见工程联调记录。

## 工作区启动

1. 为服务准备 Node.js 24.12 或更高的 24.x 版本。在 `dev/agent` 执行 `npm ci --include=optional`。安装脚本会选择本机平台的 OpenCode 1.19.6。前端依赖与 Node 版本按 devFront 启动说明。
2. 把 `.env.example` 复制为 `.env`。将 `KF_CENTER_ORIGIN` 指向开发人员登录的同一个 Center。自签名环境使用运维提供的 PEM CA，或预先独立核验的叶证书 SHA-256。KF 令牌只在浏览器、助手和 Center 之间传递。
3. 执行 `npm start`。默认只监听本机 43170。检查 `http://127.0.0.1:43170/api/assistant/health` 返回 `{"ok":true}`。可用 `KF_AGENT_DATA_DIR` 指定持久化绝对目录。每个数据目录只允许一个服务进程。
4. 在 `devFront/.env.local` 设置 `KF_DEV_BACKEND_ORIGIN` 指向同一 Center，可通过 `KF_DEV_ASSISTANT_ORIGIN` 更改助手地址。在 `devFront` 执行 `npm run dev`，打开 [开发中心](http://127.0.0.1:5175/#/login)。浏览器使用 KF 普通账号登录。开发环境 Vite 同源代理优先处理助手路由，向原生二维 HTML 注入入口脚本。
5. 在开发中心点 **开发助手 → 历史 → 新建方案**。首次打开、尚无个人方案时，直接点 **新建方案**。本机只读模式提供 **核对已保存配置** 和 **整理方案提议**。在编辑器中选 **方案清单 → 确认加入清单** 后正式版本才增加。

### 模型与证据

<!-- modified by jinlong.feng at 2026-11-20 KF助手模型统一答复 -->
模型默认关闭。使用云端或客户本机的 OpenAI 兼容端点时，配置 `KF_AGENT_ENABLE_MODEL=true`、`KF_MODEL_BASE_URL`、`KF_MODEL_ID`、`KF_MODEL_API_KEY` 并重启服务。专用密钥由部署方保管。支持 HTTPS 和本机回环 HTTP。本机 M6 验收入口单独为本场普通账号启用了 DeepSeek。其他入口的授权和配置分别管理。

启用后，OpenCode 每段对话使用独立目录和原生会话。服务端只能给当轮进程分配一个只读 MCP，查询对象绑定到发送提问时的 KF 登录态与工程入口。外部请求包含用户问题、必要的近期提问、匿名输入引用与已保存证据摘要。提问框的自由文本会作为用户输入发送；运行方需要自行确定模型和数据范围。Center 地址、KF 令牌、原始项目配置、原生历史数据库与工具列表均留在助手侧。历史和方案读取按当前工程权限再校验。

启用模型后的自由提问统一交给 OpenCode。模型结合本轮按普通账号权限读取的证据、可见的近期对话和 KF 操作资料组织正文。模型撰写的自然语言答复在同一端点复核依据后显示。需要原始变量名等本地字段时，助手只在最终展示时展开引用。当前证据和上次读回的快照分别标注；历史快照带读取时间。如果核验要求修正，模型可以按顺序选用已核实的操作、成功条件、事实或澄清问题。遇到不可核实的答复，界面显示服务提示。

每条消息的“来源”区分模型撰写、模型选用 KF 指引、模型引用 KF 查询、本机只读查询和服务提示。已追溯的旧回复会注明原来的组装方式，其余旧回复显示“历史回复 · 来源未记录”。可展开证据查看范围和时间。显式按钮“核对已保存配置”和“整理方案提议”沿用本机流程。

在仓库根目录用 Node 24 运行 `node docs/audits/kf-assistant-m6-20261120/replay-answer-routing.mjs --check`。追加 `--prose` 可用同一组六种场景逐字核对自然语言正文。两种模式均检查操作、验证条件和逐条来源。M6 现场与回放记录

### 浮窗版试点

本轮使用 `KF-Development-Assistant-M1-Floating-20261120.zip`。将它解压到独立目录，按下文启动。若从先前的 M1 试点升级，可继续使用已运行的同版助手服务和个人数据目录，仅将前端静态入口、资源和二维挂载脚本作为一批切换。回退时恢复上一包的整批前端文件，浏览器重新加载开发中心并重新打开二维标签页。

普通账号可按以下三步核对浮窗。

1. 在开发中心顶栏打开“开发助手”，拖动标题栏，写一条草稿。点黄色减号，再从右下角恢复，检查位置和草稿。
2. 从客户端工程的页面列表打开二维编辑器，在新标签页核对已保存配置。最小化时画布可操作，恢复后能继续查看刚才的答复。
3. 从周期脚本的“询问此脚本”打开同一方案。输入框聚焦时，中文选词期间的 Enter、Esc 交给输入法；结束组合输入后，Esc 收起窗口。可点击脚本编辑区继续工作，再从工具栏恢复助手。

维护人员在完整工作区、安装好前端依赖后，可复用 `python3 scripts/package-kf-assistant-pilot.py outputs/<新版本文件名>.zip`。脚本重新编译两个前端入口，校验 ZIP 并输出 SHA-256。展开实景 · 收起实景

## 备份与恢复

单实例试点使用 SQLite。停助手后将整个 `KF_AGENT_DATA_DIR` 备份到仅服务管理员可读的位置。该目录含个人方案数据库、每段对话的 OpenCode 数据、会话映射和本地缓存。还原到一个新目录时，保持服务账号权限、相同 Center 和依赖版本，再以该目录启动单实例。未结束的轮次在重启时标记为中断。核对方案版本、条目正文和两段历史，再从原入口接着提问。运行中的 SQLite 主文件不能单独复制作为完整备份。

OpenCode 将原生会话与工作目录关联。原目录重启时继续使用原生会话；换绝对路径还原时，助手保留原 KF 方案和对话，在新的原生会话中按当前权限读回历史证据。两种恢复方式均已用本机模型端点实测。

在 `dev/agent` 执行 `npm test`。项目包含普通账号共享同工程和撤权、消息取消及按游标续接、版本冲突、备份读回、KF 语法和模型回包约束的回归用例。现场记录与剩余门槛见实施计划第 7 节。

## 单节点运行画面核对

本机试点使用普通开发账号在二维编辑器选中一个文字控件。在 Chrome 扩展管理页打开开发者模式，选择“加载已解压的扩展程序”，指定源码或试点包里的 `dev/agent/runtime-observer`。从 KF 打开目标 App 并以同一普通账号登录，在实际运行页单击扩展 **KF 运行画面核对**，图标显示 KF 表示已关联，再次单击解除。回到开发中心原生二维标签，打开 **工程工具 → 核对发布与运行画面 → 查询**，或在原对话询问“这次修改在这个 App 生效了吗？”。

扩展按用户选定的单个标签授权，本机入口限定在 localhost 或 127.0.0.1 的 5179、5175、4175 端口。无扩展可查 Center 和运维记录。页面源文件与可见文字来自用户浏览器，有权的 App 和节点归属由 Center 重验。运行观察超过 45 秒即失效。正式共享站点如需接入，须配置其实际开发中心来源。现场复测过程与读数见单节点验收。

## 从原对话核对数采与报警窗

普通账号在二维编辑器单选实时报警窗，切到目标对话，在“工程工具 → 联查采样与报警”填写完整点名。运行页用同一普通账号登录并显式关联浏览器扩展。开始联查后可在测试设备上复现状态变化，点击“结束并保存”后在原对话询问每笔样本和报警窗状态。该查询使用数采监视及浏览器观察，两端必须可按同一节点的有权实例和配置匹配。每段对话保留最近一批，问答记录仍可按当时的权限范围重新核验后读取。

部署方应核对数采节点的时区；对无时区的源时间在助手环境中设置 KF_AGENT_SOURCE_UTC_OFFSET，例如 +08:00。升级本机试点时，已安装的未打包 Chrome 扩展须重新加载并重新关联运行标签页。停用 App 后仍可按当前权限复查已记录的批次。普通账号实测、逐笔回执和复测命令

## 从空工程开始

在开发中心打开开发助手，首次使用先建个人方案。可直接提问“已有能读数的实时源，只需要一个二维画面。我要用哪些工程，从哪一步开始？”；也可以在「工程工具 → 方案起步」选择输入来源和交付目标，点「查询」。需要盘点旧工程时，在「查找候选」选一种工程类别。结果给出涉及的入口、按依赖排列的操作及每步的验证方法。

方案起步是只读建议，开发人员负责决定复用哪个工程以及是否更新个人方案清单。仅需路线时不会查工程分组或目录。候选来自当前普通账号本次可见的分组和独立的工程权限核对，名称和工程标识留在本机。每次最多取 8 个分组、复核 32 项并展示 8 个候选。分组目录之外的直接共享工程需从已知入口核实。多种来源组合可分支查询，再核对交接点；具体控件、驱动参数、脚本和运行结果仍用相应入口取证。完整流程、卡点与优先级
