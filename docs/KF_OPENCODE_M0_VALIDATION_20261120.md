# KF 开发助手 · OpenCode M0 现场验证

2026-11-20，在 `192.0.2.1` 的既有供水站客户端和计算工程上，普通开发人员从二维控件追到了实时源点，再从周期脚本追到了同一输入和独立的写回点。OpenCode 服务在两次提问之间重启，第二轮仍引用了第一轮的证据。**可以用 OpenCode 进入 M1，优先建设 KF 账号、方案、入口和证据服务。** 本轮实际访问了 KF 开发态的已保存配置，服务部署方式为工作站旁路原型。首版技术架构与实施计划 · 结构化验收记录

## 四项结果

| 验收项 | 实际操作与观测 | 已验证范围 |
| --- | --- | --- |

## 本轮运行边界

- **KF 侧。** A 使用 `测试普通账号`。管理员仅在 KF 用户管理中建立一个无案例角色的普通账号 B。工程读取、助手会话和个人方案操作均使用普通身份。适配器在每次查询前读取 KF 当前用户，按租户及账号校验，并在当前工程列表里核对创建者。该策略覆盖本人创建的案例；角色共享项目、同一项目的两位授权用户及撤权后的历史证据须单独验收。
- **OpenCode 侧。** 使用官方 ARM64 运行包 1.19.6。两个实例分别监听回环地址，独立认证和数据目录。`/global/health` 返回该版本，两实例的 `/mcp` 均显示 `connected`。原生会话保存用户消息、工具参数、结果及助手消息。测试记录的模型工具列表只有 `kf_trace`。
- **业务侧。** 测试宿主管理个人方案、对话到 OpenCode 会话的映射、待确认变更、本人决定和版本。用 SQLite 事务复演提交。一个方案可对应多段对话。角色共享、正式网页接口、会话进程池和 PostgreSQL 备份恢复进入后续阶段。
- **模型侧。** 在取得本轮明确授权后，向固定的 DeepSeek 端点发送定型测试问题、对象类别、订阅状态、读写方向、匿名引用和证据编号。适配器从白名单字段重新组装消息；原始字段、工程名、点名、账号、地址、令牌、脚本及页面文件保留在本机。请求的模型别名为 `deepseek-v4-flash`，供应商响应标识为 `deepseek-flash`。回环适配器将供应商完整答复封装为 OpenCode 接受的事件流，端到端逐字输出、取消及断线续传仍需测试。[DeepSeek 模型与接口](https://api-docs.deepseek.com/)

## 如何复核这两条引用

另用普通账号登录 KF 原生界面对照。客户端页面列表显示 `StationPressure`，点击页面名打开了独立二维编辑器窗口。在一次新的普通登录中，从计算工程的周期性脚本列表打开 `PressureAverage`，看到了脚本编辑区。这两次浏览器操作验证对象和入口；OpenCode 的跨工程对话由旁路宿主切换上下文。原生控件选区自动跟随仍是 M2 的验收项。

| 工程入口 | 普通账号正式查询 | 字段比对 |
| --- | --- | --- |
| 客户端管理 → 默认工程组 → `测试工程-2` → 页面管理 → `StationPressure` | 用 `GET /client/batchGetPageFile` 定位 `PressureValue` 及其页面脚本，再读取 `GET /client/getVariableList`、`GET /client/getDataSourceList`。路径均相对于 KF 的 `/api`。 | 脚本把 `$System.P_OUT` 用于 `PressureValue.setText`。工程变量已订阅。`projectDataSourceId` 对上本工程连接 ID，连接别名为 `Rt`，实时源为 `测试工程-1`，源点名为 `P_OUT`。 |
| 计算管理 → 默认工程组 → `测试工程-4` → 脚本 → 周期性脚本 → `PressureAverage` | 用 `GET /calculation/projectJsonData` 分别读取 `periods` 与 `dataAccess`，按该脚本的 ID 读取 `GET /calculation/scriptData`。 | `KIOQueryDatas` 的输入常量是 `P_OUT`，`KIOUpdateDatas` 的写回常量是 `P_AVG5_TEXT`。计算工程自己的 `Rt` 指向同一实时源。比较的是实际连接目标与输入点的组合，两个工程里别名同名只提供查找线索。 |

本例解析了已知脚本写法中的常量和调用，并核对目标字段唯一。跨租户、同名实例、运行时拼接点名和脚本变体仍需专门用例。生产解析器要带对象稳定标识、引用层、权限、字段来源与版本；M0 的短摘要只用于这两次比对。本轮没有采集新运行值、报警事件、节点制品或未保存草稿。既有供水站发布联调结果另有记录。客户端只读接口 · 计算只读接口 · 供水站客户操作手册

## 如何复演四项验收

1. 用两位同租户普通用户分别登录，读回各自的 `userInfo`。A 能在自己的工程列表定位上述两项，B 没有案例角色。为两人分别准备隔离的 OpenCode 数据目录，读取目标运行包自身的 `/doc` 核对会话与 MCP 的 API。
2. 在个人方案下新建一段对话，由宿主保存账号、方案与原生会话的映射。设置客户端入口，发送“当前在客户端工程。请查询二维控件的已保存输入关系，列出订阅状态、匿名输入和证据编号。”检查原生消息中的 `tool` 部件、工具名、入口参数、完成状态和新产生的证据编号，再与正式读回对照。
3. 停止这个测试 OpenCode 进程，保留数据目录。重新认证后用同一个人对话切到计算入口，发送“现在切到计算工程，继续上一轮。请查询周期脚本的已保存读写关系，比较两个工程的输入，列出两次证据编号，拟一条待本人确认的方案项。”检查只新增一次计算读取，消息历史中两轮均存在，回答引用相应证据。另开一段对话时应分配新原生会话、读取同一正式方案。
4. 登录 B，先打开 B 自己的方案和会话，验证正例。接着用 B 查询 A 的个人方案、历史和待确认差异，检查统一的资源不可见结果；检查 B 的原生会话列表和 MCP 拒绝回包。只看到空列表不足以通过此项。
5. 用 A 生成草案，记下草案 ID、基础版本和当前正式清单。分别测试 B 代确认、A 拒绝、A 明确确认、重放同一决定、另一条基于旧版本的提议。每次重新读取清单并核对版本、条数和决定记录。模型原文中的“待确认”只产生草稿；正式入口把开发人员针对该差异的决定单独交给业务库。

## 首次失败怎样改变了设计

初次云端请求允许 `entry` 同时取 `hmi` 或 `calc`。模型在客户端问题上发起两次查询，两条均读到了 A 有权查看的数据。适配器把一条助手消息里的两个工具调用拆成两条助手消息，回传时没有保持配对，该轮以 `APIError` 结束。修复后，适配器按消息原样分组工具调用。宿主按已选工程收窄参数，MCP 在执行前对入口和本轮额度作原子校验。新会话复测的两轮各有一次完成的调用。只改系统提示词不足以约束查询范围。

| 修复后的真实云端轮次 | 供应商往返 | 输入 token | 输出 token | 成功调用的 KF 工具 |
| --- | ---: | ---: | ---: | ---: |
| 客户端引用查询 | 2 | 510 | 94 | 1 |
| 重启后的计算工程续聊 | 2 | 803 | 240 | 1 |
| 合计 | 4 | 1,313 | 334 | 2 |

数字为供应商按请求返回的 usage 之和，包含前文和工具定义重复计入的部分。失败轮另有一份成功的工具选择回执（347 输入、83 输出），已从上表分开。没有进行同模型、同题的全量工程输入对照，本轮无法给出节省百分比。
