本清单回答三个问题。客户在 KF 3.6 的哪个入口做什么？当前试点助手能给到哪个层次的帮助？下一次开发能让哪些工程共同受益？维护时先按对象、动作和证据维护本表，再用不同行业的任务验收。供水站的压力和园区的功率共用同一套引用解析。

## 怎么读这张表

每行对应一个有明确范围的客户动作。**指导**指助手已有与动作相符的界面路径和操作或核对方法。**配置**指普通账号能通过助手重读目标的已保存配置。**运行**指普通账号能用助手取得该行动所需的目标实例回执。开发时看到选区、静态检查通过、已有现场截图分别记在说明中。

- **实**表示列出的动作范围已有直接实现或证据。**限**表示只覆盖说明中的部分。**缺**表示在本轮审阅的助手实现中未找到专门依据，优先级另评。**免**表示该动作本身不以该层为验收目标。三列独立计数。
- “指导实”可用于给步骤，不能自动承诺用户照做即成功。“运行实”同时注明取证入口。外部测试脚本取得的结果归现场基线。M6 独立操作与 M7 盲测仍按原计划验收。
- 每行最后一列是开发态路由键。可在源码索引按该键查看实际 Vue 页面、菜单、前端请求封装以及服务端登记。独立编辑器、脚本宿主和运行模块另有索引。库存中的文件、路由、接口和业务动作各用自己的计数单位。
- 首版范围为这份源码中的五类开发工程及直接相关的发布联调。登录、容器和管理入口单列。对驱动、数据源适配器、具体控件属性和版本扩展，只有核对到明确入口与字段的子集才可写进助手的指导。路由受安装配置与账号过滤。

## 分工程维护与验收

每类工程单独维护覆盖对象、运行态依据、最近实测、当前交付状态和下一项。工程专属工具按当前入口提供，跨工程工具按当前账号逐次复核生产者和消费者的权限。某一类工程取得新结果时，只更新该工程及实际参与验收的跨工程链路。

| 工程类型 | 当前基线 | 下一项／状态 |
| --- | --- | --- |
| 计算 | 11 个叶子菜单涵盖六类脚本、数据词典、数据源和三类依赖。六类脚本均有独立 App 实测，各自边界见下表。 | PostgreSQL 连接已按工程别名对齐原生测试与 App 回包，Linux KIO 数值 IO 词典已验初值、同步、坏质量及恢复。三类脚本依赖已在同一独立实例各验一组正反例。 |
| 数采 | 驱动、设备、点表、实时值、质量和源时间已有部分普通账号实测。 | 通信参数、存储与转发、OPC 分支独立排期。 |
| 数据源 | 工业实时源与上游数采关联可用于部分追踪。 | 历史、关系库等适配器各自的连接、读写和失败回执分别验收。计算工程里的连接别名只计入计算配置。 |
| 报警 | 保存的报警规则及单节点单级高报的发生、保持、恢复已有实测。 | 多级、离散和延时分别验收。 |
| 客户端 | 二维、报表和 3D 按对象留存实测范围。 | **暂停**。已保存页面、App 提供的页面和当前标签加载版本的比对尚待验收。详见实施计划第 23 节。 |
| 跨工程方案 | 输入来源、显式引用、开发人员确认的个人清单与跨入口对话已有基础。计算需求从选中对象查引用，关联对象保留候选或外部依赖身份。 | 业务目标、算法口径、输入和输出的结构化确认及撤权后的跨入口复验单列在第 24 节。 |

### 第一项如何验收

第一项建议扩展现有 `find_objects` 和 `trace_refs`。候选查找接受对象类别、当前工程，以及可选的名称或标识；先查本工程已经配置的连接，再按需查询有权上游。每次只返回限量候选、本地引用键和仍缺的字段。引用解析复用同一组权限检查和消歧函数，对每一跳记录起点、终点、方向、配置层和证据编号。操作技能负责「何时查询、怎样验证、何时询问设备资料」。源索引留在本机供开发和检索，模型只接收命中项和本轮必需的证据。

| 给助手的起点 | 合格表现 | 需要的最小证据 |
| --- | --- | --- |
| 普通账号在二维新标签选中显示控件，表示已建好一个采集点，询问如何绑定 | 承接已完成步骤，先定位当前客户端和控件；已有相符映射就指导使用，缺映射就指导「数据源管理 → 工程变量 → 快速添加」。模型根据证据选择下一步。 | 当前标签的工程及选区；目标单条映射；有权源、数采工程、目标设备和点的唯一对应。每一跳附来源和观察时间。 |
| 不同工程有同名点，或上游授权已撤回 | 有多个可见候选时只问能消歧的一项。授权不足只说明该跳无法核实，答复与历史重放均不暴露不可见对象名称或数量。 | 当前账号重验；覆盖唯一、重复、空、拒绝四种结果。 |
| 开发人员已报出采集点；换成温度或流量设备；或设备确实尚未建点 | 有可核实的点就复用。尚缺设备资料才询问协议或对应测量项。改变设备名、单位和阈值仍可沿用同一流程。 | 对象标识、所需字段、已完成步骤；将用户陈述与工具事实分开。新标签中切换选区后重验受影响证据。 |
| 用户说“表里已经有了，为什么运行画面没变” | 给出能证明的最后一层和下一次观察位置。只有取得同一 App 和控件的新读数，才能确认画面更新。 | 编辑态、已保存、发布制品、节点和运行样本分别标注。回归可沿用能源七档输入及旧根组反例。现场记录 |

每轮先取入口、对象键和缺失关系。仅在需要时读取候选字段或一小段宿主资料。对同一选区和未变化的证据可引用前次结果；用户复核、重新保存、切换选区、权限变化或需要实时值时重新取相应层。首批验收也要检查无关工程和整份配置没有进入模型上下文。

## 如何随源码更新

在含 devFront、front、kf-reference 及已安装 dev/agent 依赖的工作区执行 `node scripts/audit-kf-assistant-capabilities.mjs --check`。开发态新增菜单页、请求封装、已扫描服务接口、原生文件或宿主时，按源码索引的差异复核对应行。更新本清单后执行同一脚本的 `--write`，再运行 `--check`。操作分级由开发人员依据实现和验收调整。源码入口盘点适合发现遗漏，无法独立判断一个回答是否正确。
