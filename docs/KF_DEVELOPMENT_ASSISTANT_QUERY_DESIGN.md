# KF 开发助手如何按需查询和核验

<!-- modified by jinlong.feng at 2026-11-20 KF开发助手首版技术架构与实施计划 -->
实现与排期见首版技术架构与实施计划，其中列出框架选型、跨工程引用解析、编辑至运行的证据和 M0–M7 逐步验收。
<!-- end -->

**已确认的产品决定。** 助手自动识别开发人员所在的工程，按当前问题读取相关配置，首版优先使用云端模型。记录属于开发人员账号。一个方案可以有多段对话，对话自动保存，方案清单由助手整理、开发人员确认后更新。客户在 KF 界面完成配置、发布和联调。账号与方案设计

下列工具名、技能和返回字段是拟开发的接口。开发中心已有若干底层查询，原生编辑器的选中对象、跨工程引用索引和面向助手的证据返回格式仍需实现。供水站已有普通用户实测记录，其他模块按各自构建、对象类型和测试记录标记覆盖范围。

## 1. 七个面向助手的工具

建议先用一个 KF 侧 MCP 服务承载这些工具。工具数量与底层 HTTP 接口数量相互独立。开发中心在打开助手时自动附上当前入口、工程及选中对象的轻量标识，首次回答通常可以省去一次模型调用工具的往返。

| 建议工具 | 什么时候查，输入什么 | 默认返回到什么程度 |
| --- | --- | --- |
| `get_context` 当前上下文 | 初次进入、切换编辑器、指代不清或需要恢复方案时。根据当前登录会话和入口标识定位。 | KF 构建、入口、工程类型与 GUID、选中对象、是否有未保存更改，以及当前问题相关的已确认方案条目。无工程入口可返回平台级上下文。候选方案不唯一时列出本人可见的候选。 |
| `lookup_reference` 产品知识 | 问“在哪里点、字段是什么意思、这个函数能不能用”。输入构建、平台、模块、对象类型、任务或函数名。 | 命中的界面路径、前置条件、相关字段或函数签名、最小示例、依据和适用版本。计算服务脚本、客户端页面脚本、报警脚本分别检索。 |
| `find_objects` 定位对象 | 客户只给出名字、未选中对象，或从总入口开始。输入对象种类、名称和允许的搜索范围。 | 返回少量候选的名称、类型、所属工程和可继续查询的标识。先查当前工程，再按需要扩大到已确认方案或本人可见工程。 |
| `read_object` 查配置 | 已经知道对象，要确认具体字段。输入对象标识与所需字段，也可请求某个字段的现场可选值或某段脚本。 | 例如一个控件的绑定、一个报表数据集的参数、一条高限规则、当前驱动的寄存器类型。每项注明来自已保存配置还是当前编辑器草稿；无法取得草稿时提示用户核对编辑器。 |
| `trace_refs` 追引用 | 问“这个值从哪里来”“改名会影响谁”。输入起点、上游或下游、关系类型与范围。 | 本地解析别名、映射、订阅、读写、资源引用等关系。先返回相关的一层或一条能回答问题的路径，附依据、候选和未解析项。反向查询结果较多时先按工程和对象类型统计，再展开指定分支。 |
| `read_runtime` 查现场证据 | 问“为什么发布后没效果”“写回是否成功”，或需要签收。输入目标节点、App、点或事件及时间窗口。 | 按需返回发布与部署标识、状态、少量点值及质量和源时间、报警发生/恢复、相关日志摘录。请求指定客户端画面时，只有实际画面观测才能证明渲染；缺少可读入口就请客户给出该处截图或读数。 |
| `validate_candidate` 校验方案或脚本 | 给出脚本、配置建议或验收结论之前。输入校验类别、候选片段、环境约定与相关证据。 | 返回通过项、失败项、依赖未满足项和定位。可做静态校验、用脱敏样本复算；需要执行候选脚本的样例仅在隔离环境使用模拟依赖。分别标注静态结果、样例结果和 KF 实机证据。 |

**工具的共同约定。** 普通账号的租户和身份由服务端登录会话确定。每次读取、反向索引、计数、分页和缓存命中都执行当前权限检查。云端只收到允许字段，连接凭据、令牌和无关脚本留在客户侧。工具返回字段值、来源标识、构建或可用修订、观察时间、缺失项，必要时再给下一页游标。可见范围内没有匹配、版本未知、多候选、结果截断分别表示；没有准确部署版本时保留未知。MCP 可声明 `readOnlyHint`，实际只读由 KF 服务端限定可调用操作和参数。连接测试、脚本试运行、发布或启停等动作需独立判断其副作用。聊天存储与方案确认走助手自身的数据服务。[MCP 工具注解](https://modelcontextprotocol.io/specification/2025-11-25/schema#toolannotations)

## 2. 技能决定何时查、查到哪里停

每个技能保存触发问题、最少所需事实、查询路线、停止条件和缺证据时问客户的一个具体问题。先按当前任务加载一项，任务跨模块时再接续下一项。

| 技能 | 最短查询路线 | 给客户的结论需要什么依据 |
| --- | --- | --- |
| 解决方案设计与续做 | 读已确认的业务目标、输入输出、验收标准和进度；列出本次需求涉及的工程，再定位已有对象。 | 能解释每个工程负责什么、哪些可以复用、还有哪些业务规则待确认。新决定形成清单草稿。 |
| 数采配置 | 从平台、设备和驱动查可选寄存器，再核对地址、采样、类型、读写、转发。涵盖对应版本的 Modbus、OPC 等入口。 | 填表指导要有该驱动的字段依据；“已采到”还需要新鲜的源时间、值和质量。 |
| 数据源与接口 | 先辨明实时、历史、关系库或报警事件，再查适配器、工程内别名、目标及所需的读、订阅或写能力。 | 能指明生产者、消费者、连接和操作方向。历史查询、实时订阅与写回分别核验。 |
| 计算脚本 | 先定周期、数据变化、条件、请求或系统触发，再查当前运行环境的函数、参数、读写目标、自定义函数和依赖。 | 给出能放入对应编辑器的脚本正文、测试输入和预期输出；要声称已在该版本运行，另需实机结果。 |
| 报警 | 查输入点、词典、规则、死区与延时，再沿报警工程、事件数据源和客户端过滤条件核对。 | 规则说明可据配置回答；发生、恢复或确认要有对应事件、时间和对象。 |
| 二维客户端 | 从当前页面、控件或图形模型查属性、工程变量、事件脚本、模板引用、页面访问策略。国际化、快捷键等按所问对象查。 | 能定位用户要编辑的对象和属性。需要判断画面表现时，要有当前运行页或客户现场观察。 |
| 3D 客户端 | 从工程、场景、模型、场景对象逐级定位，只取所问资源、属性或绑定。打开失败时分别看资源、编辑器连接与画布加载。 | 场景已登记、模型已加载、变量已驱动对象是三个可分别验证的结论。大模型文件留在本地。 |
| 趋势与报表 | 从趋势控件或报表单元查序列/数据集、数据源、参数、时间窗、时区及字段映射。 | 能区分查询无记录、参数不匹配和有数据但未显示；有必要时取最小一行样本。 |
| 发布、权限与联调 | 从工程 GUID 查发布版本、节点和 App，再区分工程组权限、工程内安全对象与运行账号。按问题读取状态、日志或画面。 | 能指出第一个有证据的差异及验证动作。发布成功、进程运行、用户能打开页面和业务值正确分别记录。 |

平台首页及工程组入口也适用。新建、复制、导入导出等生命周期问题，先按工程种类查操作资料。用户、角色、分组可见性、系统日志、授权和节点问题，由发布与权限技能按当前用户可见范围定位。权限、版本与引用影响分析贯穿各技能。

知识库的覆盖单位是一个具体操作。例如“3D 打开场景”和“3D 对象绑定”各有条目。每条记前端入口、保存字段、运行消费者、来源和已验证范围。先从路由、原生编辑器菜单和函数目录建清单，再逐条补依据；已编目的入口、已核对的源码、已实测的参考环境和已验证的客户现场分别展示。五类工程和流程 · 开发中心路由

## 3. 确定性函数承担哪些判断

这些是工具内部可独立测试的函数。路由和校验在 KF 侧完成，云端模型无需逐个调用。

| 函数职责 | 具体规则与输出 |
| --- | --- |
| 选择查询步骤 | 输入问题意图、所在入口和已有证据，按技能规则找出回答需要的字段，返回最小查询计划和停止条件。意图仍有歧义时，问一个能缩小范围的问题。 |
| 解析对象与别名 | 用租户、工程 GUID、对象类别、局部 ID 和工程内别名确定对象。同名候选保留所属工程。客户说的业务名称可匹配候选，不能直接建立引用。 |
| 提取和遍历引用 | 解析结构化字段和脚本中可静态识别的引用，建立正向及反向索引，处理循环与重复。遇到运行时拼接的点名、未加载插件或不完整索引，返回覆盖范围与缺口。 |
| 校验字段与数据源能力 | 核对必填项、枚举、单位、类型、读写方向、驱动和适配器支持。例：由设备和寄存器取得现场可选类型，由结果点属性核对写入条件。 |
| 校验脚本契约 | 解析候选正文，检查语法、脚本宿主、触发器、函数签名、异步返回、点名和输出类型。动态调用或外部依赖无法静态判定时列明待测项。 |
| 复算样例 | 按业务规则比较输入、预期和实际，处理时间、质量、空值、边界、恢复等。五点均压和高报只是两个可插拔的规则，其他任务使用自己的样例。 |
| 比对版本和证据 | 对齐工程、发布版、节点、App、时间窗及对象，比较预期与实测。识别旧截图、部分成功和过期数据，输出哪些结论成立、失败或仍待验证。 |
| 控制模型输入 | 按字段投影、脱敏、去重、分页和任务预算截取结果；缓存以账号权限范围和构建/修订为条件。运行读数附时间，过期重取。被省略的分支和未取的正文可按标识继续查。 |

## 4. 三条实际可执行的路由规则

| 用户的问题 | 助手第一步 | 何时继续，何时停止 |
| --- | --- | --- |
| “在这里如何新建请求式计算脚本？” | 从入口确定是计算工程，按构建查询请求式脚本的菜单、输入输出及函数约定。 | 查到匹配该版本的步骤就能回答。只有用户要求按自己的数据写正文时，才读取相关数据源别名和变量。 |
| “这个月报为何是空的？” | 定位当前报表和数据集，读参数、时间区间和字段映射。 | 若已发现参数类型与已声明类型冲突，可先指出并给验证步骤。若配置相符，再查关联数据源的一条受权历史样本；数据集有值时才检查单元绑定或部署版本。 |
| “这个变量改名会影响哪些工程？” | 定位到唯一变量，查询下游引用，先按页面、计算、报警、报表等分组返回数量。 | 有修改计划时再展开具体字段。若存在脚本运行时拼接名称或只覆盖部分工程，回答“在当前账号可查询范围内已找到这些引用”，并给出待核实位置。 |

## 5. 如何同时验收准确率和 token 用量

每道验收题预先标记正确对象、必需证据、允许的结论、无需读取的材料和该找不到什么时应追问。例如同名点不能串工程，过期均压不能认作本轮结果，查按钮位置不能读取整份点表。先对比“整包输入”和“按需读取”在同一组脱敏参考工程、同一模型上的结果，再定各类问题预算。记录正确率、无依据的确定性结论、必要引用漏查数、调用次数，以及每题**累计**模型输入 token 的中位数与 P95；分别记录首问、追问和跨入口续聊。权限变更、未保存编辑、点名动态拼接和版本无法确认都应有测试题。

首批验收应同时包含一条跨工程实测链和若干不同入口的独立任务。供水站可核对均压写回和发生/恢复；再用未参与知识编写的工程考查请求式脚本、历史报表、3D 场景和变量影响分析。预算不足且仍缺决定性证据时，返回已知范围和下一项核对动作。产品版本更新后按受影响入口、函数和适配器重验。普通账号供水站实测 · 供水站专项规则与函数

## 6. 对接源码的起点

- 开发中心可从当前路由和工程状态取入口标识。二维和 3D 原生编辑器应各自提供当前页面、场景、选中对象及草稿状态的只读摘要。页面查询、3D 资源信息和报表查询在客户端工程已有独立入口。客户端工程查询 · 3D 资源入口
- 数采的寄存器列表带工程、设备上下文，寄存器类型还取决于寄存器名称。数据源、报警和计算有各自的配置及查询入口，可在本地转换成所需字段和引用。数采 · 数据源 · 报警 · 计算
- 脚本知识分别绑定计算运行服务和客户端运行服务。运维对接按操作逐个审核，只开放与当前用户和目标 App 匹配的状态及证据查询。计算运行函数 · 客户端运行函数 · 运维 App 接口

## 7. 首版效果评估

评估依据为开发中心前端、Center 与 Node 的对应实现、运维监视代码、普通用户操作记录及已导出的真实页面。本次做了离线源码核对与页面字段提取。下表是完成适配后的交付判断，当前尚无新助手在陌生工程上独立指导客户的成功率、时延或 token 基准。

| 客户想做的事 | 首版可达到的效果 | 依据与仍需补齐的部分 |
| --- | --- | --- |
| 从任一入口接着开发 | 在主要工程管理页面自动定位工程，恢复本人的方案与多段对话。进入计算脚本或报表后可以针对正在编辑的内容给建议。 | 客户端、计算、报警及数采有各自的工程状态。报表编辑器记录工作簿、工作表、行列；脚本编辑器单独维护改动并在保存时提交。要解释未保存的修改，编辑器须提供当前内容或选区摘要。个人方案和对话历史由新助手实现。客户端工程状态 · 报表选区 · 脚本编辑状态 |
| 配设备、数采点、数据源和报警 | 在已覆盖的驱动与适配器上，能给出当前表单该填什么、字段之间的约束；能发现选错设备、点类型或工程内别名等有证据的问题。 | 驱动列表按工程平台与操作系统查，可选寄存器按设备查，可选类型再按寄存器查。报警工程保存目标数据源名称和 GUID。外部 PLC 的地址约定、项目量程、客户报警策略仍需要现场资料或人员确认。数采查询 · 报警源配置 |
| 接手已有工程并追到上下游 | 可解释结构化映射、已识别表达式及静态脚本中的常见读写，给出每段引用及可核对的位置。 | 客户端快速添加支持变量改名，同时保存源点名、别名和订阅状态，源 ID 允许为空。计算运行时还会按租户和服务名找 App。解析器需要处理不同标识、缺字段和多实例。脚本动态拼接或外部调用要报告未解析范围，不能据此宣称改名影响已经列全。变量映射 · 计算运行寻址 |
