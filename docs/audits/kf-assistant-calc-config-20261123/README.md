# 计算工程配置与运行接口首轮验收

2026-11-23 在本机独立开发版，使用普通开发账号读取 192.0.2.1 的测试工程 `测试工程-9`。现场验证仅使用工程配置和只读引用。浏览器使用临时个人库，此次验证没有更新现有 M6 发布版本。

## 从开发中心实际操作

1. 在计算管理的默认工程组打开测试工程。选择「数据词典」，打开开发助手，在「工程工具」选择「计算配置回读」，点「查询」。现场返回 9 条词典变量，列内标注初始值。新建变量的原生入口为「数据词典 → 新建变量」。
2. 切到同一工程的「数据源管理」，再次查询。现场只返回该工程已保存的一条连接，工程内名为 `BenchRt`。建立连接时点「新建」，选平台数据源并填写工程内名称，保存后在此处复查。
3. 在「工程工具」改选「计算运行接口」。输入 `SQLQuery` 并查询，可见 Node 源码位置、参数、第三个参数接收结果行以及默认超时 3000 毫秒。这一步验证了浏览器中的用法查询。实际关系库结果仍需在相应适配器和测试实例取证。
4. 对现有周期性脚本 `ScaleReading` 发起包含计算目标的方案查询。现场追到 `BenchInput`、`BenchResult`、对应的实时源和数采工程，共返回 4 条已保存关系。结果单独标明仍需核对连接名与部署实例的对应。源工程对方案的归属由开发人员确认。

## 运行接口与工程隔离

- 以本地 Node 计算运行态的 globalFunc 注册入口为准，核对 13 个直接注册模块、77 个命名全局符号。该计数限定于此入口。脚本宿主、词典变量和自定义函数由各自模块加载。
- 17 个详细条目涵盖 10 个已核对用法的注册函数、词典全局变量访问，以及六类宿主与调用约定。按名称查到仅登记的函数时会显示缺少详细约定。不在索引中的符号保持未核实。运行用法来自工作区版本，实例实际运行与结果单独取证。
- 真实 OpenCode 配合本地模型替身，在同一段测试对话先查询计算词典，再查 SQLQuery，校验两次工具来源和本地名称展示。模型侧收到配置数量、状态和操作指引，本机事实保留实名变量和示例。本轮未将工程问题发送到云端。
- OpenCode 工具白名单、MCP 公布工具和服务端校验使用同一套入口范围。周期与请求编辑器可以查询计算运行接口；客户端、数采、报警、数据源入口分别使用自己的工具。跨工程续聊仍可按当前账号查询已关联的计算回执。

## 复查方式

在仓库根目录使用工作区 Node 24。现场脚本沿用此前计算验收的普通账号登录入口，口令在本机读取。浏览器检查接受一个已构建的 devFront 目录，临时启动前后端，完成后关闭进程。前端依赖若按不同架构安装，可用环境变量 KF_UI_NODE_BINARY 指向相匹配的 Node 可执行文件。

- 现场菜单及引用复查
- 真实浏览器操作
- 配置与权限回归
- 运行源码与工程入口回归

首轮完成配置回读、按当前选区取已保存引用、运行接口检索和本机测试。业务口径跨入口确认、按新需求生成完整候选、其他宿主的实际执行、各适配器在目标版本的查询与异常分支，按实施计划第 24 节独立验收。
