# 从计算数据词典的 IO 变量核对实例读数

普通开发人员在词典勾选一个 IO 变量后，助手按工程、分组和行 ID 重读保存配置，核对别名、实时源、上游数采工程、设备和点名。取运行证据时，助手再核对实时源配置的 REST 地址与数采 App、目标计算 App 和已保存请求脚本。重名、撤权或取证期间映射改变会阻止本次归因。

## 从原对话验收

1. 打开本机 M6，用原普通账号登录。进入「计算管理 → 默认工程组 → 测试工程-28 → 数据词典」，在左侧复选框单选 `MeasuredTension`。
2. 打开「开发助手」，切回「园区能源总览 → 第一段对话」。在「工程工具」选「所选 IO 变量与实例读数」并点「查询」。第一行是词典保存的初值，第二行给出映射路径，后续每行对应目标 App 的一次真实响应。源时间使用 KF 回包原文，调用时间以带 Z 的 UTC 显示。
3. 自由提问可用「这个变量对应哪个设备点？把保存的初值、App 的首次读数、坏质量和恢复读数列出来，并说明质量与源时间来自哪里。」本轮实机验收覆盖原对话中的工程工具。模型入口沿用同一只读工具，本轮没有向云端发送问题或现场数据。
4. 如需取得新样本，在这次验收工程直接选择目标 App，输入已有只读请求脚本名 `ReadTensionSnapshot`，点「关联一次请求回包」。通过已登录的业务调用端向该请求脚本发起一次 normal 调用，导出包含响应正文的 HAR，回到词典选入并重新「查询」。HAR 在浏览器内解析，助手只接收取证窗口内匹配目标地址的业务观察。
5. 换到自己的计算工程时，先查询所选变量，复制工具提供的只读脚本正文，在该工程创建一个启用的请求式脚本，使用相同的脚本名与函数名，保存并部署至要验证的 App。代码会读取两次实例词典值，中间通过 `KIOQueryDatas` 读取一个点。采样期间词典发生变化时，报告显示两次读数。工程缺少该脚本时，仍可查看保存映射，补齐取证入口后再取得运行样本。

## 冻结后的现场结果

通用回归 120 项通过，冻结服务版 `391743c2ebe3`。随后新建卷材张力数采、平台实时源和计算工程，使用普通账号勾选词典行，并在同一 App 导入五次真实调用。映射为 `MeasuredTension → WebInput → 测试工程-29 → 测试工程-30 / RollBench / RollTensionRaw`。冻结清单 · 回包、监视与源时间 · 浏览器验收

| 采样条件 | 保存初值 | 实例词典值 | App 读取的采集点 | App 取得的源时间（北京时间） |
| --- | ---: | ---: | --- | --- |
| 启动时模拟器持续返回读异常，上游在线 | 713 | 0 | 0，Q=0 | 15:35:44.714 |
| 停止独立数采和实时源，仅重启计算 App | 713 | 713 | 无样本，读取码 14001 | 未知 |
| 恢复上游并成功同步 | 713 | 84 | 84，Q=192 | 15:39:07.668 |
| 模拟器继续返回读异常，寄存器设为 137 | 713 | 84 | 84，Q=0 | 15:39:11.662 |
| 恢复模拟器正常读取 | 713 | 137 | 137，Q=192 | 15:39:36.987 |

第一轮验收脚本假设坏质量启动后首次读取仍等于初值，实测得到 0。保留观察，再增加停上游重启计算 App 的对照，才在运行中直接读到 713。数采重启后的首次重新连接也超过了原定观察窗口，重新等到模拟器收到 3.32 的读取、数采监视恢复良好，再作同步判断。验收期间调整了测试步骤和等待时间，产品保持冻结。恢复测试后独立 App 与专用模拟器保留在线。模拟器位于开发机，重新取样需要开发机在线。

M6 迁入这一工程的五条回执后，浏览器以原账号从原对话逐行复查，与候选版相同。发布前后原 13 轮对话、方案版本及原有计算、报表、连接回执的摘要一致。此次实测没有调用外部模型。

## 证据含义

计算宿主初始化时将保存的 `value` 赋给 `global` 中的同名变量。KIO 订阅更新该变量，订阅处理对字面质量 `Bad` 有单独处理。运行中读取 `global` 只能得到变量值。接口 `KIOQueryDatas` 则读取目标点，Linux 数采适配器把点名、值、质量和源时间分别放入 `N/V/Q/T`。报告把两种观察放在一次实际调用内；对无样本的调用保留读取码，将质量和源时间标为未知。词典初始化 · 订阅赋值与读取 · Linux 适配器

当前实机范围是一个 Linux KIO 实时源、REST 读取、单个数值 IO 变量和一个目标实例。坏质量阶段比较同一映射、同一 App、同一请求路径此前的良好观察与本次词典值。两次采样值相同只能说明两个时刻读数相同；进程重启、两次采样间发生的写入，以及每次订阅赋值都需要额外的执行记录。字符串或布尔 IO 的现场同步、其他适配器、纯内存词典的点质量均单独登记。
