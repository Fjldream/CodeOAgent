# KF 计算助手 · 自定义函数与跨宿主调用

冻结版本 `44d7365895f6` 已通过 109 项通用回归。冻结后从原有方案选取未用过的色码校验业务，在 192.0.2.1 普通开发账号的独立计算 App `测试工程-16` 验证复用、定义、调用和写回。选题与验收预期

## 开发人员怎样使用

在计算工程打开“自定义函数”，双击函数可从“询问此脚本”进入助手，也可从周期或请求式脚本提出业务需求。描述输入顺序、返回类型、异常口径以及哪个调用方消费结果。助手可以复用当前工程启用的函数；需要新增时，一次给出函数名称、形参和正文，以及所需调用方的完整代码。工程实际名称在本机还原。简单的参数直返、二元运算和部分 Math 返回表达式提供可核对的语义摘要。复杂已有函数若只有签名，仍需确认业务约定。

开发态分别保存显示名、functionName 和逗号连接的有序 paramlist。Center 保存正文时包装为 `module.exports = async function(...)`；Node 过滤启用项，按 functionName 注册已加载的模块。周期和请求式调用均可用 `await global函数名`。普通 return 提供函数结果，缺少返回值时得到 undefined；请求式调用方负责把值放入 OutParam 并结束应答。助手生成的调用使用明确的有序实参，校验引用、参数个数和 await。新函数名与当前词典、函数及已知宿主名称冲突时会退回修订。开发态函数配置 · Center 正文包装 · Node 模块注册

## 独立盲验

原方案校验四字符色码：前两位是 AB 或 BA，后两位为 ASCII 数字。测试工程提前保存一个通用的双字符串拼接函数，显示名为“拼接选项”，调用名为 `PairText`。没有预置色码函数。真实模型从工程取材后新增 `checkColorCode(prefix, suffix)`，在函数体中复用 `PairText`。周期及请求两份调用方均等待同一个新函数；普通账号回读确认原拼接函数、签名及启用状态符合预置。

首稿的匿名读写点和新函数引用校验失败，模型根据诊断自行完成第二稿。三份最终正文逐字存在于对话中，工程回读只多出 KF 包装的两个尾部换行，各自的指纹见回执。新函数原稿 · 周期原稿 · 请求原稿

周期从两个模拟寄存器按高低字节解码两段输入，保存实际使用的参数和函数返回值，向第三个寄存器写 1 或 0。请求式脚本单独接收两段字符串，在真实 HTTP 回包中返回实参和布尔结果。只读探针取得周期回执，并独立调用原拼接函数核对返回值。设备端 Modbus 日志用于核对实际写入，各档同时确认 KF 三个点的读数和质量。

| 实参顺序 | 原拼接函数实测返回 | 周期取得的返回值 | 请求回包 ok | 实际设备写入 |
|---|---|---|---|---:|
| `AB`、`07` | `AB07` | `true` | `true` | 1 |
| `BA`、`00` | `BA00` | `true` | `true` | 1 |
| `AA`、`12` | `AA12` | `false` | `false` | 0 |
| `AB`、`1X` | `AB1X` | `false` | `false` | 0 |
| `BA`、`99` | `BA99` | `true` | `true` | 1 |

另外发送了两组纯 HTTP 请求。后缀长度不足的 AB、7 与前缀错误的 ZZ、00 均返回 false。每档数字字符串保留前导零。首次固定 3 秒取证时，有一档未在窗口内截到下一笔设备写入，已保留该次记录。正式复测沿用同一已部署原稿，在周期结果稳定后等到新的设备写请求才判定。

本机 M6 已切换，并按原账号复核原对话和历史摘要。实机结论覆盖本次两位置参数、字符串与布尔返回值、数采写回及 HTTP 回包。大型工程的已有函数正文取材为有界读取；复杂副作用、动态函数调用和任意返回路径尚不能仅靠静态校验确定。现场回执
