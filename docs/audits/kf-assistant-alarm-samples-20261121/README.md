# 园区能源 · 原对话核对实际采样与报警窗

2026-11-21，普通账号在 192.0.2.1 的 test 节点完成两轮七档模拟电表回归。试点为本机 5179。操作对象是独立案例的模拟输入、数采 App、实时源、报警 App、事件源和运行客户端。测试程序用真实 KF 数采监视 WebSocket 读取 ActivePowerRaw，通过已登录的 Chrome 运行页扩展读取 EnergyOverviewM6 页面选中的原生报警窗 M6EnergyLiveAlarms。独立断言还核对了可见功率控件的 kW 读数以及报警窗原始行。首轮观察 · 试点逐笔回执

## 再次查询或记录

1. 读取上次结果时，在本机试点以原普通账号打开“开发助手 → 历史 → 园区能源总览 → 第一段对话”。已有答复可直接查看。也可提问“请列出本段对话最近一次联查中，各笔数采值、质量、源时间，以及同一条报警的发生、保持和恢复。”
2. 记录新过程时，先确认目标实例均已部署运行。在 Chrome 中用同一普通账号打开运行 App 的目标页面，展示原生实时报警窗。在该标签页点击“KF 运行画面核对”扩展，图标显示 KF。已加载旧版的用户先在扩展管理页重新加载工作区的 runtime-observer，再关联目标标签。
3. 从对应的开发态二维编辑器单选同一个报警窗，打开原方案及目标对话，选择“工程工具 → 联查采样与报警”，填写完整采集点名，点“开始联查”。在独立模拟设备上复现变化，等候窗口显示恢复并取得下一笔采样，点击“结束并保存”。每次最多记录 90 秒或 60 笔。结束后可从该对话的其他工程入口发问。工具保留该对话最近一批，既有问答中的回执按当时结果保存。
4. 观察范围为当前运行窗显示的事件行。同名词条、多条同时匹配、跨节点或权限不足时无法确认唯一关系。未取得好质量与新鲜源时间时只报告缺项。空窗只说明观察时该窗没有匹配行。源时间未自带时区时，运行方须确认现场 UTC 偏移并配置 KF_AGENT_SOURCE_UTC_OFFSET。报警窗使用浏览器解释的显示时间，本轮浏览器与节点使用北京时间。
