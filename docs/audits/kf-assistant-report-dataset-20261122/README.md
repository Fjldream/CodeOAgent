## 重新取证

1. 在开发态保存报表，选中绑定单元格，打开「询问当前单元格 → 工程工具 → 报表数据集回读」。点「查询」可以先读保存关系和当前对话的历史观察。
2. 点「关联报表查询」。使用同一账号打开目标客户端运行 App。在 Chrome 开发者工具的 Network 清空记录，刷新一次报表，将目标格滚动到可见区域。点工具栏的「KF 运行画面核对」关联此标签页。已安装旧版扩展时，先在扩展管理页重新加载工作区的 dev/agent/runtime-observer。
3. 导出含正文的 HAR，保留本次页面文档和 getReportData 请求。在助手中选取该文件。助手在浏览器中提取目标字段，按文档、时间和应用实例核对。多次加载或缺失同页证据时，重新采集。单次窗口为十分钟。
4. 如需核对实际 InParam，展开「补充同次脚本执行回执」。填写业务系统每次调用生成且在返回行中唯一的关联字段，选择本次脚本原调用的 HAR，或脚本端保存并按同一标识查出的执行回执 HAR。本例使用 invocation。开发人员可对同一专用脚本提交 normal 请求，InParam 中的 receiptFor 取报表回包中的 invocation。此操作只读取该测试脚本保留的最近 32 条业务记录。其他脚本的回执须能提供 input、relation 类型的 output 和 invocation，或者保留原业务调用。助手不会发起这类脚本调用。
5. 点「核对运行单元格」。分别检查入参、脚本返回行、数据集字段、单元格原值及显示文本。缺少同次脚本回执时，助手保留已核实的客户端回包和显示结果，并标出上游缺口。选同一报表的其他单元格，结果按新的选区过滤。

本轮覆盖自定义数据集的关系型标量返回，以及所选绑定锚点的首行。历史型、SQL 型、多行展开中的非锚点、任意业务回执格式和运行进程的源码版本仍待验收。原始 HAR 保留在开发人员浏览器一侧，工具投影只向模型提供状态和数量。现场测试不向云端发送脚本、业务字段或数值。
