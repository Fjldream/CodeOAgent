## 原对话中的变更

助手基于开发人员有权读取的原工程、已交付脚本的需求清单和最新提问，再次回读工程关系和计算工程引用。变更清单列出沿用、作废、当前有效口径及写回目标的去留。每次生成前重新核对工程，校验新版本的目标和宿主。正式方案清单单独确认，此次仍为第 0 版。当前已测试请求式脚本和内存变量。其他宿主及 IO 写回尚无本项的实机证明。

冻结前通过 159 项开发回归和 29 项试点回归。冻结后从既有仓储方案的库位状态统计中派生一道独立变更题，在原普通账号的原对话先生成初版，再从关联数采入口改变口径和写回目标。初版只统计空闲，变更版统计空闲和锁定。两版均由真实 DeepSeek 生成，在同一个请求端点先后保存。读回比对的唯一区别是工程保存时末尾增加两个换行。冻结清单 · 独立预期

验收中有两次额外交互。首次变更清单把工程连接列为脚本输入，验收者退回清单并重申输入沿用请求参数，助手重新查证后移除了多余引用。回复“确认生成完整 JS”被模型识别成继续修改，多展示了一轮清单。使用界面提示的“确认生成”后交付。确认前未生成新版 JS，也没有将草稿写入开发人员的正式方案。

## 独立实例的写入计数

3.32 的 测试工程-24 在同一次首次部署中运行最终业务端点及仅作对照的初版副本。初版与修订版使用同一个实例内的两个不同词典变量。测试观察器在两个测试变量赋值时分别计数，包括同值赋值，测试结束后恢复其普通属性。对照数据包括初版 1 次及变更后 7 次请求。

| 请求 | 回包 | 旧目标累计写入 | 新目标累计写入 |
| --- | ---: | ---: | ---: |
| 初版，E、L、F、L | 1 | 1 | 0 |
| 改后，同样输入 | 3 | 1 | 1 |
| 改后，L、L、C | 2 | 1 | 2 |
| 改后，均不纳入 | 0 | 1 | 3 |
| 改后，空数组 | 0 | 1 | 4 |
| 改后，含未知状态 | null | 1 | 4 |
| 改后，输入为 null | null | 1 | 4 |
| 改后，恢复有效输入 L | 1 | 1 | 5 |
