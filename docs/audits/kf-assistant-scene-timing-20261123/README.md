# 用原对话核对三维自旋转与可见性闪烁

用原普通账号打开[本机 M6](http://127.0.0.1:5179/)，在「园区能源总览 → 第一段对话」提问“Fan 和 Beacon 绑定的点在 1 和 0 两档时，各自的保存规则、实测转速和完整闪烁周期是多少？关闭后观察了多久？”已有记录可直接回读。

## 从选区重新测量

1. 在「客户端管理 → 测试工程-8」进入测试副本 **测试工程-41**，打开「3D 资源管理」，双击 **TimingBench**。原生编辑器会打开新标签。若显示未命名画布，双击场景列表中同名缩略图。
2. 单选左边长条 **Fan** 或右边方块 **Beacon**，打开「开发助手 → 园区能源总览 → 第一段对话 → 工程工具 → 三维部件绑定回读」，点「查询」。两者经页面 **EnergyStatementView** 的 **TimingLayout** 订阅工程布尔变量 `$$TravelInput`，再经实时源连接 **MotionRt** 映射到模拟设备 **TravelBench** 的 **BenchInput**。
3. 要录入新观察，在 Chrome 扩展管理页重新加载本机 KF 运行画面核对扩展，用相同账号打开[测试运行客户端](http://192.0.2.1:23654/)，单击扩展使标签出现 KF 标志。将编辑和运行标签放在同一浏览器窗口。保持部件中心无遮挡和镜头固定。
4. 将独立模拟点切换为 1。稳定后点「记录第一次画面」。扩展会短暂激活运行标签，连续观察几秒后返回。再切到 0，点「记录第二次画面」。对另一个部件重复。当前现场结果已取得，无需写模拟点即可验收原对话。记录操作结束已将模拟器恢复为 23。

## 普通账号现场结果

2026-11-23 在 192.0.2.1 由普通账号 `测试普通账号` 完成。Fan 保存为 Z 轴顺时针中速，每 40 ms 前进 4°，标称 100°/s，约 16.67 rpm。Beacon 保存为中速可见性闪烁，每 600 ms 切换一次，完整显隐周期为 1200 ms。两档都是启停输入。每次观察前后分别取得同一数采点、同一稳定值、源时间和质量 192。

| 部件 | 源时间（北京时间） | 数采点 / 客户端布尔值 | 画面观察 |
| --- | --- | --- | --- |
| Fan | 09:35:27.824 | 1 / true | 实测转速 99.86°/s（16.64 rpm） / 标称 100.00°/s，观察 3.32 s，轮廓变化 34 次 |
| Fan | 09:35:33.837 | 0 / false | 实测转速 0.00°/s（0.00 rpm） / 标称 0.00°/s，观察 3.34 s，轮廓变化 0 次 |
| Beacon | 09:35:41.820 | 1 / true | 实测闪烁周期 1206 ms / 标称 1200 ms，观察 3.96 s，完整周期 2 个 |

转速用同一运行节点绕指定轴的实际角度变化和单调时钟计算，同时检查屏幕固定位置能否拾取到转动的轮廓。闪烁要求显隐状态、同一部件的拾取与实际渲染像素同时变化。若隐藏后画布透明，则核对底下可确定的纯色背景。用两次同相位切换之间的时间测完整周期。当前验收要求运行方向一致、转速与标称相差不超过 12%，并逐段检查转动连续性。闪烁至少取得两个完整周期，每个同相位间隔与标称相差不超过 15%。后台节流、遮挡、点值变化、像素无可辨差异或采样稀疏时，界面提示重试或保留差异。

Fan 选区与回执 · Beacon 选区与回执

两份原对话回执为 `匿名标识-20`（Fan）和 `匿名标识-21`（Beacon）。测试开始时独立数采 App 测试工程-38 需要启动，复验期间保留运行。

## 复测入口

- 普通账号原生界面测试使用 `--timing`；正式本机试点增加 `--pilot`。在完整工作区根目录用 Node 24 运行。环境变量 `KF_M6_CALC_SIM_INPUT` 指向初值为 23 的独立模拟器输入文件，`KF_SCENE_QA_DIR` 指向已创建的截图目录。测试结束恢复原值。
- 同账号原对话与选区隔离复查在相同目录运行，正式本机试点增加 `--pilot`。OpenCode 对话回放使用 `--timing` 与 `KF_SCENE_REPLAY_DB`。回放在对话副本使用本机测试模型，原对话仅增加两份主动采集的运行记录。
