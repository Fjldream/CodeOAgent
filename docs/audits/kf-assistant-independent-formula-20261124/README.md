# 确认公式独立执行的首次冻结与盲验

版本 `a013aa313ae7` 开发态回归 179/179，试点回归 52/52。条件设计只提供合成输入、初值、故障和覆盖条款。两个独立模型请求根据同一份已确认条款生成纯函数体，每个条件单独创建有时间、内存上限的本机 QuickJS 实例。候选脚本稍后由独立的 KF 宿主生成流程提交。保存参考正文、样本、执行结果、版本指纹；失败的公式检查也有对话诊断。

冻结后从现有的重复任务时间筛选逻辑派生批次登记跨度统计。初版对各组跨度求和，变更版取最大跨度。预登记两版各 10 次真实请求以及写异常测试。

| 环节 | 观察 |
|---|---|
| 原账号、原对话 | 初版清单正确识别输入、公式和输出，将“额外字段一律忽略、无需再问”放进待答问题。第一次确认又返回清单，未交付 JS，单次确认验收失败。 |
| 同题补测 | 原样重复一次确认，无业务纠正。两份模型公式实际在本机对 24 条相同条件执行。一个任务在第 10、50 分钟登记、另一任务单独登记时，两份公式都算出 40；第二份还把输入数组放进了回包。 |
| 故障条件 | 两份公式对两条写异常都预测了成功写入。按预登记规则，抛错应回 null 并停写。第一份参考输出完整符合 22/24 个条件，第二份完整符合 1/24。 |
| 用户可见诊断 | 补测回复给出第一条输入与两份参考输出，服务阻止候选生成。在这个阶段还没有候选 JS 的实际值。 |
| 独立 App | 普通账号核实专用 App 正常运行。此题建立两支测试变量，候选保存 0 次，真实业务请求 0 次。变更版未开始，M6 未更新。 |
