# 计算工程系统事件脚本

本机 M6 使用冻结版 `c3173188b112`。助手从当前计算工程取有权限的词典、连接和已登记的 KC 接口，根据需求一次生成两段无参完整 JS。工具分别校验工程引用、宿主参数和语法，错误附阶段与行号，可回交模型修订。对话显示两份本机绑定后的正文。每段正文有独立的编辑和保存位置。

## 开发人员入口

1. 打开目标计算工程，在「脚本 → 系统脚本」列表中双击「系统_应用程序启动时」或「系统_应用程序关闭时」。
2. 在当前标签点「询问此脚本」，说明初始化要读取哪些输入、要写什么状态，以及收尾结果需要保留到哪里。若业务要求停机必达，先核对目标运行包和实际停止路径。
3. 按回答的阶段标题分别复制正文到对应编辑器，保存后重开这两行核对。每个事件有自己的固定 GUID，编辑器同时携带当前工程标识。
4. 在隔离 App 将运维状态、运行值与追加日志核对。启动后查一次，停止时确认实例离线，原 App 重启后回读完整历史。把初始化期间留下的关闭记录归入该次启动窗口。进程内变量重启会复位，次数核对需要能跨进程保留的证据。

## 源码与可用函数

开发界面按 `systemScripts` 查事件列表，用工程 ID、事件 GUID 读正文，双击后打开脚本编辑器。Node 的 `start()` 先初始化词典与 KC 函数，等待数据源初始化，再初始化脚本，HTTP 服务随后监听。在脚本初始化内部，工程自定义函数先于系统事件注册。数学、文件、实时点、数据库等函数可从运行态注册表按符号查询。具体适配器需要当前工程的连接、权限和可用数据。请求式宿主专有的入参和应答函数不能用于系统事件。开发态入口 · Node 初始化 · 脚本注册顺序

| 实现 | 初始化 | 退出 |
|---|---|---|
| Node 阅读快照 | 先调用启动正文，随后误调关闭正文。不等待启动 Promise | 缓存的是关闭调用返回的 Promise，退出钩子中的函数类型检查不能再调用它 |
| Center 的工程模板 | 调用启动正文，保留关闭函数引用 | 执行到退出钩子时调用关闭函数，宿主未等待异步收尾 |
| 3.32 此轮两个独立 App | 每次启动各留下一条启动记录 | 运维停止、重启后累计回读均为零条关闭记录 |

同一项目树中可以查到两种宿主。普通账号的现场记录能说明业务结果；它没有辨认远端实际运行文件的哈希或停止信号。关键的最终写入需要独立确认。本次改动范围为开发助手。Node 宿主 · 退出钩子 · 工程模板宿主

关闭正文被调用时是否能保存正确快照，在本机分别装载两种真实宿主管理器，执行同一对话中的原稿，以捕获写入的测试函数记录结果。对清理会话位 0、1 各运行一次。Node 快照在初始化期间写快照，工程模板在显式调用退出钩子时写快照，四次结果都与当次配置逐字一致。实机停机成功执行收尾仍缺少正向回执。宿主回放 · 回放程序
