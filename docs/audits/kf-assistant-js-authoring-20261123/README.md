# 完整 JS 候选与运行依据

## 版本依据

开发中心通过 calculation/projectJsonData 读取指定计算工程内的 dataAccess、globalVars、functions 及各宿主配置，通过 calculation/scriptData 按工程、类型、对象标识读写正文。源码入口为 devFront/src/api/allRequest/calculationAPI.js 和 Center 的 kingcalculation/exe/lib/services/ScriptService.js。助手取材使用当前普通开发账号的只读访问。部署、触发、实例读数与已保存工程分别取证。

Node 计算服务源码根目录为 kf-reference/KingFusion3.6_Node/kingexedb/kingcalculation/exe/lib。init/globalFunc.js 加载 13 个函数族，直接登记的 77 个名字及包装参数来自 service/globalFuncMng。每个模块的源码摘要与公开登记清单保存在 dev/agent/src/kc-registrations.ts，使用 index-source.mjs --check 可检查漂移。包装参数个数、已核实的详细调用用法和目标适配器实际回包是不同层次。委托给底层库的函数保持其委托标记；DLL 的注册还受操作系统约束。

| 宿主 | 开发态配置 | Node 运行入口（service/globalScriptMng 下） | 编写或验收要点 |
| --- | --- | --- | --- |
| 周期 | periods | periodicScript/periodScript.js | 配置决定间隔或日历，脚本提供每次调度的正文。检查重复触发、异步完成和外部写回。 |
| 请求 | APIs | onDemandCalcScript/onDemandCalcScript.js | 正文使用 InParam、OutParam、RequestID，回包调用 endResponse(RequestID)。响应路径、超时和并发需要运行验证。 |
| 数据变化 | dataChanges | dataChangeEventScript/dataChangeScript.js | InParam 来自触发类型。已保存绑定与实际事件载荷分别核对。 |
| 条件事件 | conditions | conditionEventScript/condition_script.js | 条件进入、存在、离开对应不同正文；应定位具体阶段并分别验触发顺序。 |
| 系统 | systemScripts | systemScript/systemScript.js | 应用启动和关闭采用各自事件。按开发人员指定用途编写。 |
| 工程自定义函数 | functions | customFunction/customFunction.js | 按已配置名称及形参定义编写正文，调用方按同步或异步返回约定取结果。 |

## 工具协作

inspect_script_environment 按当前工程读取连接、实时源关联的有权采集点、数据词典和自定义函数。模型获得匿名引用、宿主信息、KC 名录及所选符号的使用资料。数量上限沿用工程目录设计。实名、工程正文与部署凭据留在本机。自定义函数参数清单在本机显示，调用语义未知时需与开发人员核对。

check_script_drafts 接受模型原创的完整 JS，允许循环、分支、局部函数、数据结构及异步调用。工具解析语法树，核对部分宿主变量、直接 KC 调用的包装参数、可解析的工程连接、显式实时读写点以及请求结束调用，将有权的字符串引用替换成 KF 实名。工具只做静态检查，动态点集合、模块依赖、运行状态、超时、所有控制流是否恰好回包一次都需要相应验收。诊断和模型原稿可用于同轮修订；未通过的稿件不能显示为已通过正文。宿主如需多阶段配置，模型需指明该正文的目标阶段。

项目只读，JS 生成工具不加载或执行提交的代码。仅在独立验收 App 由验收工装保存、部署和调用审阅过的候选。开发阶段使用语法、宿主、参数、引用、撤权和同轮修订测试，不放入验收业务题。
