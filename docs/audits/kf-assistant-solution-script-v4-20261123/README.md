# 确认前校验、计算脚本与对话轮次导航联合发布

本机 M6 的 5179 入口已启用脚本版本 `fe77eb8136f3` 与对话轮次导航。原普通账号打开「园区能源总览 → 第一段对话」，左侧刻度定位到最后一次“确认生成”即可查看完整 JS。原有消息、个人方案第 0 版及提议摘要通过一致性检查。正式入口浏览器实际显示 93 轮，已验证预览、点击、键盘首末轮与滚动高亮，并从刻度打开此次 JS 所在的轮次。

## 助手新增的能力

工具在本机将用户点名的工程变量解析为当前工程可读的引用。确认清单分别展示待生成脚本、输入、输出和复用函数。明确的输出和宿主约束随同一任务跨入口保留；引用选择偏离这些约束时，工具向模型返回诊断和可选引用。用户先补充业务口径，再明确确认。新版本先做宿主和语法检查，再验证调用、写回与已确认清单是否一致。可追溯到同一作用域、使用前唯一赋值的引用和调用别名参与校验。脚本提交中不合法的请求函数外壳返回行号及修改方法。部署和运行回读由本次验收执行。

实际识别取决于可见工程、变量名和用户对写回或宿主的表达。错写目标、变量重名片段、改口、找不到目标、复用和新建同时出现、别名重赋值均有本地回归。歧义无法从工程查清时还需要开发人员核对。此次真实模型的错选是多选了自定义函数宿主；错写变量的修订由通用回归覆盖。

## 冻结后的独立验证

- 开发版 157 项、试点版 27 项回归通过后冻结。此前托橇重号验收失败的七份模型原稿单列回放，验证语法、回包及别名诊断能够区分。冻结清单 · 旧稿回放
- 新题取自既有仓储方案的车型码校验。普通账号从计算工程进入原对话提问，再从数采入口补口径和确认。DeepSeek 首次同时选择了 request 和 customFunction。工具拒绝多余宿主后，模型自行重选 request，并将同一个已登记函数放在复用函数清单。回复中首次显示给开发人员的清单已通过校验。仅对两道短横线的业务含义进行了确认。题源与预期
- 原对话交付的请求式脚本读 DefaultTypeCode、调用 TokenEquals 并写入 TypeCheckMemo。宿主校验从模型提交的具名请求函数提取编辑器正文，实名在本机绑定。保存时未人工改稿，3.32 工程回读与对话正文仅相差末尾两个换行；两份原始内容的 SHA-256 分别留存。运行与交付回执
- 测试所建的初始字符串“07”经 KF 词典保存接口转成了数值 7。旧试验实例缺省输入按确认口径返回 null，显式有效字符串回包和缓存正常。将测试初值调整为能原样保存的有效字符串“--”后，用同一 JS 和同一份预期重验。首次重部署时原实例停止命令轮询超时，最终使用独立实例 测试工程-44 首次部署。测试环境还保留前期专用实例 测试工程-45 和 测试工程-46，最终回执均来自 测试工程-44。
- 在最终实例先读到基线缓存 0。12 次业务请求均在同一 App 用独立观察端点复核缓存。包括缺省值、普通数字、短横线、全角数字、前导空格、空串、数值及 null，覆盖非法输入保留和有效输入恢复。覆盖单个请求完成后的缓存观察；未注入内存赋值失败或做并发压测。
