# 园区今日用电量 · 计算脚本生成与 M6 实机验收

2026-11-23，普通开发账号在 192.0.2.1 的 test 节点完成九组验算。开发助手根据工程已保存的连接和点表生成两份候选正文。验收工装把这两份正文保存、回读并发布到专用计算 App。原园区客户端与原电表继续使用原配置。

## 在原对话继续

1. 刷新本机 M6 开发中心（5179），用原普通账号打开「园区能源总览 → 第一段对话」。问「从当前客户端查电表的设备点、实时源和变量。」当前工程可见 Meter01 / ActivePowerRaw、连接 Rt → M6EnergyRT 和同名客户端变量。该点表示瞬时功率。
2. 问「沿用本段对话最近验过的计算 App，按北京时间日初冻结表底差生成周期性和请求式脚本。」助手从本人本段对话的最近计算回执重新定位计算工程，并检查关联权限。这项选择随最新回执变化。需要指定其他工程时，从计算管理打开目标工程。
3. 问「刚才的今日用电量是多少？缺冻结、换表和回零各返回什么？列出实际写回和请求回包。」本段对话已关联四组各九点的监视记录及四笔真实 HAR 回包。可从原客户端入口「工程工具 → 计算脚本回读 → 查询」直接核对。
4. 也可以打开「计算管理 → 默认工程组」，搜索 测试工程-10，点击工程名，进入「数据词典 → 开发助手 → 工程工具」。先选「核对计算输入和工程变量」，再选择「日冻结表底差 · 生成周期性脚本」或「日冻结表底差 · 生成请求式脚本」，点「查询」即可复制代码。两类候选已各自通过真实浏览器复制框检查。

## 已确认的业务契约

原园区客户端读的是功率。开发人员确认在独立模拟电表增加累计电能量，以**同一电表的当前累计 kWh 减去北京时间当日 00:00 冻结的累计 kWh**。零点表底可以为 0。日初冻结无效、冻结日期不符、换表、回零时，本日结果不可计算。模拟器提供冻结数据、日序和换表/回零所需身份信息。现场设备若没有冻结表底，应补历史归档或冻结数据来源。此次没有用午夜后第一笔样本代替零点表底，也没有跨真实午夜等待取样。

| 独立工程 | 已核对的配置 |
| --- | --- |
| 测试工程-11 | FrozenMeter，Modbus TCP。只读寄存器地址 11–17 依次为当前累计、零点冻结累计、冻结日期（北京时间 Unix 日序）、当前电表编号、零点电表编号、当日回零次数、冻结有效标志。21、22 为可读写的结果与状态寄存器。本台用无符号整型，单位为整 kWh。 |
| 测试工程-12 | 工业实时源关联上述专用数采工程及该实例的实际端口。 |
| 测试工程-10 | 计算工程内别名 MeterRt。周期脚本 UpdateDailyEnergy 间隔 2 秒，请求式 ReadDailyEnergy 使用同一组采集输入。词典有 9 个已保存变量。脚本通过实时源直接读点。 |

生成器根据源连接、数采权限、设备归属、准确点名、点描述和读写属性定位业务字段。工具也接受开发人员指定的字段到点名映射。数据缺失、映射冲突、同名点或多个完整候选时需要核对。用例中每种角色对应同一台电表上的独立点；其他现场的时区、分辨率、冻结接口或换表判据需要按实际契约处理。候选代码与实名点表在本机展开。

## 实测

| 输入条件 | 周期写回的结果／状态 | 请求式实际回包 |
| --- | --- | --- |
| 当前 1280，日初 1200 | 80／1 | ok，80 kWh |
| 当前与日初都是 1200 | 0／1 | ok，0 kWh |
| 日初是 0，当前 17 | 17／1 | ok，17 kWh |
| 冻结无效 | 保留 17／3 | missing_day_start，null |
| 冻结日期为前一天 | 保留 17／3 | missing_day_start，null |
| 当前表号由 7 变为 8 | 保留 17／4 | meter_changed，null |
| 当前 1199，低于日初 1200 | 保留 17／5 | meter_reset，null |
| 已回零 1 次，当前数值再次超过日初 | 保留 17／5 | meter_reset，null |
| 恢复当日有效输入 | 80／1 | ok，80 kWh |

九笔请求均为 HTTP 200。每轮独立检查模拟设备收到的写寄存器值，并从 KF 数采监视 WebSocket 读取结果与状态、质量和源时间。数值的采集质量与业务有效性分别表示。客户端显示时只在状态码为 1 时使用结果。状态 2 表示输入读取、质量或时间检查失败。坏质量、过期时间、读写返回错误及北京时间换日的精确瞬间另用本地宿主回归覆盖。
