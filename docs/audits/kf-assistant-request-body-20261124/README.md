# 原对话一次确认与请求式正文自修

候选 `22578ffbe276` 继承了确认前的工程事实复核。请求式脚本校验能区分未调用的函数表达式、立即执行函数、宿主参数被同名形参遮蔽、回包实参数量错误。开发回归 166/166，试点回归 41/41。上个冻结版的失败单独保留在首次验收记录。

冻结后，从既有输送线库存工程选取按节点类型识别输送线的逻辑，派生独立的路线分析题。初版求最长连续输送段，变更为整条路线的输送节点总数，同时切换写回变量。验收前登记了两版的输入、回包、缓存和逐次写入数。

| 原对话操作 | 实际结果 |
| --- | --- |
| 提初版需求 | 助手自行核对词典与宿主，给出口径、输入和唯一写回变量。 |
| 回复“确认生成” | 本轮直接交付初版 JS。 |
| 改口径和写回目标 | 重新核对工程，列明沿用条件、作废口径、停止写入的目标和新的目标。 |
| 回复“确认生成完整 JS” | 首稿带有不符合请求宿主的外层声明；真实模型收到诊断后重交了完整正文，同轮交付。 |

两版依次保存到同一工程端点并回读。专用 App 另保留初版正文副本，使两个版本可以在同一组变量、同一个计数窗口里顺序测试。保存接口为每份正文追加两个换行。实测路线由两个连续输送节点、一个其他节点、再一个输送节点组成，初版回 2，变更版回 3。每版 9 次调用中合法 5 次、非法 4 次。缺参数回 null 并保持两项缓存，空数组回 0 且恰好写一次。同值重复请求分别计数。变更阶段旧目标累计写入次数保持 5，新目标从 0 增至 5。

另用同一题对错误写法做独立对照。由真实模型生成错误 KIO 写法，冻结校验器反馈连接与写入项不匹配。模型重交了完整 JS，恢复词典赋值。正式四轮原对话均无人工业务纠正或改稿。原对话的变更版曾带有未使用的局部匿名名称映射，确认说明中也可见测试别名。实际交付的工程写回目标与现场计数均已核实。

自修稿在原专用 App 独立端点的 9 次调用全部匹配。M6 已切换至本冻结版，经浏览器从原普通账号打开原对话并定位变更版正文。对话轮次导航的 121 个刻度可跳转，相邻刻度间距 7 px。
