# 计算脚本回读 · M6 普通账号验收

在本机 M6 开发中心登录原普通账号，选择「园区能源总览 / 第一段对话」。从客户端入口也可以直接问「这段对话里，周期脚本读了哪个点、把结果写到了哪里？请求式脚本实际返回了什么？」。助手按当前账号权限读回这个对话关联的记录。

## 从计算对象进入

1. 在「开发中心 → 计算管理 → 默认工程组」找到独立工程 `测试工程-9`。工程列表分页时在关键词框输入工程名并回车。
2. 展开工程内「脚本」。在「周期性脚本」双击 `ScaleReading`，点「询问此脚本」。核对助手顶部的方案及对话，展开「工程工具」，选「计算脚本回读」，点「查询」。保存配置给出工程内别名、源及读写点；每笔现场记录列出 App、时间、值和质量。
3. 需要新读数时，选运行中的目标计算 App，点「采集输入与写回点」。KF 分别向有权限的数采实例订阅已解析的点。观察以每个点自己的源时间为准。动态构造的点名、多个可选源或实例无法区分、坏质量和过期时间均应保留为待核对。
4. 在「请求式计算脚本」双击 `ComputeOffset`，点「询问此脚本 → 工程工具 → 计算脚本回读 → 查询」。展开的实际 JSON 保留数值、布尔值、空值及嵌套结构。
5. 需要关联新调用时，选目标 App，点「关联一次请求回包」。在**实际向该 App 发出请求的调用端**清空网络记录，通过正常测试入口调用一次，导出含正文的 HAR，在十分钟内选择该文件。也可使用能导出标准 HAR 的 HTTP 测试客户端。浏览器只处理与所选实例及脚本路径匹配的一个 `POST` 交易，提取 `InParam` 和响应 JSON。若报表由服务端代发请求，应在实际调用端取证。模型工具只读已经关联的回包。
6. 切回客户端入口，保留同一段对话，再次查询即可。每段对话最多保存 32 笔，每次按类型各展示最近四笔可见记录。脚本入口限定当前脚本，计算工程入口限定当前工程，其他入口查询本段对话。项目或实例权限撤回后，相关运行记录随即受限。

## 复验范围

- 两种原生脚本编辑器均按「询问此脚本」进入原对话。暂存环境实点周期采集按钮并从文件选择控件导入真实回包。本机 M6 原入口复核已保存的结果。界面测试
- 独立的数据库副本使用真实 OpenCode 和本机模型协议测试端点。从原客户端入口自由提问可得到远端实测点值及 JSON，工具交给模型的只有数量、状态和本地引用。试验没有向外部模型发送数据。对话链路
- 错实例、错脚本、跨账号、撤权、票据重放、坏质量、过期源时间、同端口归属冲突和取证中修改正文均有回归。服务端保存业务字段，完整 HAR、请求头和会话令牌留在调用端。回归用例

维护人员复跑现场工装可用 双寄存器模拟器 和 联调脚本。本轮本机在 59512 端口保留一个独立模拟器，输入文件为 `dev/agent/.state/pilots/energy-20261120/calc-bench-input`，已恢复到 23。维护人员复跑时把该文件路径赋给 `KF_M6_CALC_SIM_INPUT`。工作站重启后可用 `python3 bench.py --input <输入文件绝对路径>` 重新启动同一工装。联调脚本默认连接隔离预览，`--pilot` 连接本机 M6。普通账号登录信息从本机交接文件读取。复跑需要保留上述专用项目、实例和原始测试正文。
