# 计算工程总览与查询步骤

本机 M6 试点 `8abb12016278`。普通账号从「计算管理」打开任意有权工程，在数据词典或脚本列表问“这个工程做了什么？”。模型选择整个工程的只读工具。工程登记、变量和正文留在本机解析，回答包含业务链路、各脚本触发条件和关键处理、词典及数据源映射、实际运行记录。

工程清单沿用本版本 ScriptService.getProjectJsonData 的全分组查询（groupId 为 -1）。按六类脚本 GUID 读取正文；条件事件独立分析进入、存在、离开三个子段。通过 JS 作用域区分宿主对象与局部变量，识别登记函数、同一变量或同一连接和点上的读写关系。静态调用和共享数据并不证明运行顺序。动态函数名、无法解析的表达式或缺少的正文均标注局限。正文解说按脚本列出部分步骤。业务目标超出源码可观察行为时仍需由开发人员说明。

运行回执按当前账号、原对话、计算工程及关联 App 权限读取；正文哈希和采样时的保存版本逐笔比较，较早版本的结果单列标识。无可见回执时会直接说明。没有在本轮启动、部署或调用现场业务脚本。

## 查询过程和排版

开发助手在实际开始查询时通过现有流式通道推送步骤，完成后登记数量或结果，失败在对应步骤上标识。正在处理时展开过程，结束后可点「已完成 … 项核对」回看。权限受限的历史回合不会返回该回合的查询步骤。旧消息没有采集这些事件，保持原有显示。普通说明、标题、列表、表格、行内代码和完整代码块采用不同的排版；UI 以文本节点渲染工程名及模型内容。

## 独立验收

开发版 144 项通用测试、独立试点构建 21 项专项测试及回答格式测试通过，生产前端构建通过后冻结。独立工程选用先前已有采样记录的 测试工程-9。普通账号在原对话分别从数据词典和周期脚本列表发送同一句话。两轮真实模型均选择工程总览工具，回答全文和证据指纹一致。两轮查询各产生 5 个开始事件、5 个完成事件；在浏览器中观察到答复出现前的过程，重新打开原对话后仍可展开。试点（5179）宽窄窗口均实测，内容区没有横向溢出。

- 登记读取了 9 个词典变量、1 个数据源别名和 4 条脚本（1 条周期、1 条请求、2 条系统事件）。本工程没有登记自定义函数、数据变化或条件事件，这三类的关系分析覆盖于通用回归。
- 周期脚本 ScaleReading 每 2 秒尝试读入 BenchInput，检查质量和读取结果，再把值乘 3 加 2 写到 BenchResult。ComputeOffset 按请求参数返回数值或无效输入状态。两者为不同执行入口。
- 答案给出原对话中已有的现场样本，包括输入 23、写回 71，以及请求 HTTP 回包。对采样后保存正文有变化的回执保留历史标记，未声称本轮重新执行。
- 试点使用此前通过的 M6 基线独立合并此功能。原有回合摘要及正式清单不变，两次云端试验只发送获准的问题、菜单类别、匿名工具状态与证据占位符。
