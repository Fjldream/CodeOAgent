# 自由对话的菜单依据与需求澄清

M6 现场输入一个已保存的周期脚本名，模型回复用户位于数据词典。该轮服务端实际收到周期脚本列表的路由、工程和分组，未收到单选脚本 GUID。模型交付前未调用工具，复核只采用通用脚本操作依据。此前日历实测覆盖了工具入口、规则和 App 写回，自由对话仍能产生这条错误结论。

## 改动

生成与复核都能读取当前菜单。模型可结合近期用户目标，在本轮直接查工程、先向用户确认业务选择，或在查明事实后再澄清。由模型撰写追问；复核员核对它是否确有必要、是否在重复询问已给的信息。通过后保存问句，让下一轮短答有明确的指代。澄清阶段可以零次读取业务对象。工程事实仍须通过本轮普通账号权限核对。

对六类计算脚本菜单，若模型给出答复而尚未查过业务工具，且答复并非需求澄清，则在复核前读取本菜单。输入完整对象名时按当前工程与分组匹配。完整名称有匹配的答复须带入本地事实；在这一环节，复核员即使错误批准一段通用步骤，系统仍可纠正或展示注明来源的本机回读。同名项保留歧义。

## 验证范围

冻结版 `cd660f1985c7` 通过 130 项回归。使用普通账号读取 3.32 真实工程，用本机模型替身经过 OpenCode、服务端复核与回读四轮。两轮注入错误菜单的答复，分别在周期和请求式菜单纠正；另一轮让模型提出自拟追问，确认本轮未调用工程工具；下一轮只补充目标，无需重复对象名，真实读回该对象的已保存调度。替身用于可重复验证控制流程，此结果不衡量 DeepSeek 自行选择追问的准确率。各轮回执

本机 M6 已复核原普通账号、原对话 17 轮与既有回执。原对话未加入回放消息。后续独立验收应使用客户自然表达，同时抽查问得过多、猜得过早、听不懂补充与引用过时事实四类情况。
