# 普通开发账号从计算工程选择数据源

冻结版本 `30867237970c`，114 项通用回归通过。计算工程原生「新建」按数据源名称从平台目录选目标，将类型与工程内名称保存在连接表。第一项开发优先解决空工程没有别名、助手只返回空清单的问题。开发态界面

## 客户操作

进入计算工程的「数据源管理」，打开「开发助手 → 工程工具 → 计算配置回读」。输入完整平台源名或已有工程别名，点击「查询」。留空列出最多 24 项。在权限范围内能唯一识别、尚未关联的源标为「可选」。已有配置显示「已关联」及工程内名称。遇到同名、多个连接或类型不一致时需先核对。部署前先在原生界面「新建」，选择目标，确认类型、填写工程内名称并保存。

模型工具沿用 `inspect_calc_config`，传入 `section=dataAccess` 与 `sourceChoices=true`。仅将数量、状态和操作指引投影给模型，原始连接参数和认证字段不进入报告。返回名单前复核当前普通账号权限，含跨工程结果的对话记录保存所依赖的工程范围。当前报告标记为「已保存」，连接测试与 App 的实际读数分别取证。核对逻辑

## 现场结果

- 在 192.0.2.1 的 `测试工程-15` 中，现有连接数为 0。普通账号查询指定平台源，得到 1 个可选目标。
- 在 `测试工程-16` 中，同一目标已经关联；按平台源名和工程别名 `LabelLink` 两种方式查询，本地事实相同。两个工程的保存清单在前后两次读取中一致。
- 独立浏览器以普通账号进入第三个工程 `测试工程-9`，从开发助手查询 `BenchRt`，确认已关联为 1、运行核对为 false。本机 M6 更新后，实际工具入口也回读成功。原普通账号对话仍为 13 轮，升级前后摘要一致。
- 本地回归覆盖同名、类型变化、无权限、读完后撤权，以及超过 24 项时用完整名称命中。此次未向云端模型提交新题，未采集原生「测试连接」成功或失败回执。普通账号现场核对 · 结果摘要 · 回归用例

后续第一项是把同一别名的原生连接测试回执与目标计算 App 的实际读取关联起来。开发中心能连通与部署节点能取数需要分别验证。
