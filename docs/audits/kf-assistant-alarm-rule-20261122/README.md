# 报警词条和客户端报警窗的规则回读

## 客户操作

用参加园区能源试点的普通开发账号登录本机开发中心，进入「园区能源总览 → 第一段对话」。这段对话可从两个入口继续。

- **从词典进入**。打开「报警管理 → 测试工程-7 → M6EnergyAlarm → 数据词典」，勾选 `ActivePowerRaw` 一行。打开「开发助手 → 工程工具 → 报警规则回读」，点「查询」。应看到点名、词典连接 `Rt`、高限、死区、延时开关及恢复边界。
- **从画面进入**。打开「客户端管理 → 测试工程-8 → 测试工程-5 → 页面管理」，点击 `EnergyOverviewM6` 打开独立编辑标签，单选画面上的实时报警窗。回到浮窗的同一段对话，使用相同的查询工具。可输入完整点名 `ActivePowerRaw`。结果会列出窗 `M6EnergyLiveAlarms`、事件源别名 `Events` 和关联报警工程。多个词条时可按点名查询，同名时在词典分组内勾选目标行。

可直接问「按当前保存的规则，这条报警什么时候发生、保持和恢复？请对照本段最近的数采值、质量、源时间和报警窗限值。」运行数据需要在有权的目标 App 取样；保存配置本身可独立回读。实际事件按词条、报警项、组、类型和首发时刻关联。当前配置改过时，历史记录继续使用联查当时的规则。相同来源样本、坏质量、无唯一报警行及缺关联权限都不足以判断实际发生原因。

## 原对话与复测

本机 M6 已更新。普通账号原有 13 轮问答、方案归属和对话 ID 在升级前后摘要一致。升级后在同一段「第一段对话」通过现场联查接口重新采集以下两批。原报警词条、原客户端工程、原页面和原报警窗均相同。两个入口均可回读两组并区分当前配置与联查时的配置。

| 高限 | 本段联查编号 | 发生、保持、恢复的数采源时间（北京时间） |
| --- | --- | --- |
| 790 | `d3703b970944cb78d195ba56f1fea4f2` | 12:10:30.336、12:10:33.337、12:10:34.345 |
| 800 | `0751aa4ed8fd4ab0a29b20f212873ee5` | 12:11:09.323、12:11:12.330、12:11:13.338 |

测试结束后原词条恢复为 800/49，原报警 App 运行，模拟电表回到 60 kW，数采 App 恢复为测试前的停止状态。临时副本的三个 App 已停止，工程保留。查询这两批历史记录时可直接使用原对话。

在本机试点从仓库根用 Node 24 运行以下验收。浏览器验收需要 Chrome 与工作区 Playwright；普通账号口令通过 `KF_M6_PASSWORD_FILE` 或本机现有交接文件提供。

- `node docs/audits/kf-assistant-alarm-rule-20261122/check-ui.mjs --pilot` 在词典和原生编辑器查询历史记录。
- `node docs/audits/kf-assistant-alarm-rule-20261122/check-field.mjs --cycle-rules --pilot` 是现场变更测试。它调整专用词条、发布、切换供数和重启专用实例，完成两个七档对照后恢复。普通客户查询规则使用上方只读入口。

## 证据范围

- Center 工程文件决定当前选中的报警窗、词条及保存配置。助手只提供只读查询。现场验收脚本使用专用普通账号维护测试数据。
- 自动比对覆盖单节点、原生实时报警窗和单级限值报警。多级限值和布尔词条有保存条件说明。延时持续期间、多级切换、离散报警实机回执和自定义报警在后续验收。
- 只在本人有权的当前对话回读最近四批带规则快照的记录。历史运行记录同时复核原页面、关联工程与目标实例权限。自由提问经真实 OpenCode 和本机模型测试端点验证；试点用户的云端原对话由本人继续使用。
