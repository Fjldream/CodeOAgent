# M6 开发任务单 · 园区能源总览

交给独立操作的开发人员。使用你自己的普通 KF 开发账号。开始前向观察员确认你没有参与过供水站案例，并告诉观察员是否做过本能源工程。

## 你要交付的结果

在 192.0.2.1 的「园区能源总览」测试工程中接入一块模拟电表。值班人员打开运行客户端后，要能在已有的能源总览画面上看到电表当前的有功功率、单位，以及功率过高后的报警和恢复。页面上原有的演示数字需要能和本次接入的实测值区分。

本题业务口径为 **达到 80 kW 发生高报，降至 75 kW 或以下恢复**。观察员会提供三个依次稳定的功率值 **60 → 90 → 70 kW**，并可按你的要求重复供数。请同时验证 **79、80、76、75 kW** 四个边界值，说明在什么值发生、保持、恢复。现场如需等待采样或报警延时，可主动要求保持当前输入。

## 开始与交付

1. 自己登录开发中心，打开开发助手，为本次能源任务建个人方案。你可以自行提问、使用助手内的工程工具、切换工程或继续历史对话；方案提议由你本人确认。
2. 按助手给出的指引完成任务。遇到卡点时，保留当前页面，先告诉观察员你问了什么、助手如何回答、你试到了哪里。观察员会记录所缺信息。若有人需要给具体做法或代操作，请标记从哪一步起得到了帮助。
3. 完成后，在运行客户端向观察员演示功率变化与报警发生、保持和恢复，指出这笔数据来自哪块表。让观察员记录对应的运行样本、画面、报警事件时间和发布目标。请勿将登录口令或令牌写入记录。

## 从已打开的二维编辑器开始实操

你现在打开的是客户端工程 `测试工程-5` 的页面 `EnergyOverviewM6`。请保留编辑器标签和「园区能源总览 → 第一段对话」。这次用同一个普通账号亲自配置。下面是观察员提供的操作流程，按有人工指引的模拟测试登记。工程名和点名是本场建议值，若你已按相同用途建过对象，先核对再接着做。

### 1　从客户端切到数采工程

1. 在浏览器顶部点原来的「开发中心」标签。如果它停在客户端工程内部，点「返回工程列表」。
2. 在左侧树展开「数采管理」，单击组 `测试工程-20`。右侧点「新建工程」，名称填 `M6EnergyIO`，运行平台选 **Linux**，点「确定」。
3. 单击列表里蓝色的 `M6EnergyIO`。左侧出现「数采设备」「数采变量」「转发配置」就到位了。此时可在原对话记录已完成建工程。

### 2　接入一块表，建一个只读点

| 位置 | 点击与填写 | 成功时核对 |
| --- | --- | --- |
| 数采设备 → 新建设备 | 名称 `Meter01`，打开「激活」。设备地址填 `192.0.2.2 59510 7`，三段用空格隔开。「设备驱动 → 选择」中选 **Modicon / Linux / ModbusTCP** 并确定。链路类型选 TCP。如果界面仍显示「串口名称」，该框填 `192.0.2.2`。点「确定」。 | 设备列表同一行能看到 `Meter01`、ModbusTCP、完整地址和激活状态。 |
| 数采变量 → 新建 | 名称 `ActivePowerRaw`，关联设备选 `Meter01`，寄存器名称选 `4`，寄存器地址填 `11`。寄存器类型和转换后类型均选 `Ushort`，读写类型选「只读」，采集频率填 `1000` ms，转换模式保留「无」。点「确定」。 | 搜索点名并回车，同一行读回设备、地址和类型。这里 4 区第 11 个字对应电表的保持寄存器 40011、协议偏移 10。此点保留原始计数，600 代表 60.0 kW。 |
| 转发配置 → 新建 | 转发类型选 `WellinTech-MQTT`，主题选「亚控主题」，提供商填 `M6EnergyMQ`。本节点既有测试 Broker 的配置为 `127.0.0.1:23883`，连接模式「匿名无加密」，选「间隔转发」，周期 `1000` ms，心跳 `60` 秒，重连 `3` 秒，服务质量 `0`。点「确定」。 | 列表读回转发地址和周期。该地址指向节点上的测试 Broker。订阅是否收到本次功率变化在第 6 步核对。 |

### 3　发布数采，在 3.32 上读到第一笔功率

1. 点「返回工程列表」，勾选 `M6EnergyIO`，点「发布」，等该行显示「已发布」。复制这一行的**工程 ID**，第 4 步要用。
2. 用同一账号登录[运维中心](https://192.0.2.1/opscenter/main)。进入「运维节点管理 → test」，核对节点 IP 为 `192.0.2.1`。在「app管理 → 添加 → 名称旁的选择」中展开「采集工程 → 测试工程-20」，单击 `M6EnergyIO` 并确定。给本场新 App 填节点分配的空闲端口，记作**数采端口**。后续几个 App 各用自己的空闲端口。若已存在本场对应实例，沿用该行显示的端口。
3. 选择「快速部署」，勾选刚添加的行，依次点「部署 → 确定」「启动 → 确定」。在该行出现「已部署 / 已运行」后，点同一行的「监视(端口)」。在**监视窗口内**输入 `ActivePowerRaw` 并按回车。
4. 电表保持 60 kW 时，应读到 **600**、好质量（本版正常值为 **192**）。隔两秒再看，应仍为 600 且源时间更新。保留两次的点名、值、质量和源时间。如果是 `--`、坏质量或恒为 0，先停在这里，把这几列和设备地址交给观察员。观察员可核对模拟器是否收到了来自 3.32 的 FC03 读请求。工作站在 11 月 21 日 08:05 实读 600，本场 KF 节点的首笔读数留给你验证。

### 4　把数采点接到报警工程和客户端工程

1. 回到开发中心，点左侧**一级菜单**「数据源管理 → 测试工程-34 → 新建工程」。名称填 `M6EnergyRT`，类型选「工业数据源_网络模式」，数据来源选 `KingIOServerLinux`。获取变量列表方式和实时数据回写方式都选 `restful`。
2. 「工程ID」粘贴第 3 步复制的 ID，「工程实例名」填实际数采实例名（按本流程为 `M6EnergyIO`）。「实时数据发布主题」填 `datachange_S_KIOL_` 紧接该 ID。填 `emqx_ip = 127.0.0.1`、`emqx_port = 23883`，匿名 Broker 的用户、密码留空。填 `restful_ip = 127.0.0.1`、`restful_port = 第 3 步的数采端口`。「连接配置」的用户名和密码填获准访问该数采服务的测试凭据，如尚未交接，在这一步向观察员领取。点「确定」。按第 3 步发布，在节点「添加 → 数据源工程」选择 `M6EnergyRT`，快速部署并启动。
3. 在「报警管理 → 测试工程-7 → 新建工程」建 `M6EnergyAlarm`。单击工程名，在**工程内**点「数据源管理 → 新建」，数据源选 `M6EnergyRT`，名称填 `Rt`。点「数据词典 → 快速添加」，数据源名称选 `Rt`，输入 `ActivePowerRaw` 并查询，勾选该点、确定。列表应有这个数采点。
4. 在「客户端管理 → 测试工程-8」单击已有工程 `测试工程-5`。在**工程内**点「数据源管理 → 新建」，数据源同样选 `M6EnergyRT`，名称填 `Rt`。到「工程变量 → 快速添加」，选 `Rt`，勾选 `ActivePowerRaw` 并确定。回列表搜索完整点名，核对「关联数据源名称」为 `Rt`，「映射Tag名称」为 `ActivePowerRaw`。若下拉没有该点，返回核对实时源的工程 ID、实例名和数采端口。

### 5　设定 80 kW 高报和 75 kW 恢复

1. 回到 `M6EnergyAlarm → 数据词典`，在 `ActivePowerRaw` 行点「编辑 → 报警属性」。勾选「启用报警」「限值报警」「高」，高限填 **800**，报警文本填「园区总有功功率高」，优先级填 `1`。启用**限值报警的死区**并填 **49**，延时保持 0，只启用这一档高限。点「确定」，再打开这行，核对高限、死区开关、死区数值。发布报警工程，在节点添加该「报警工程」、快速部署并启动。
2. **49 是原始计数。** 工作区此版报警程序在点值达到高限时触发，在点值严格小于「高限减死区」时恢复。因此 800 触发，751 仍保持，750 首次满足恢复条件，对应 75.0 kW。按本页的整数点配置填写，现场用第 7 步验证。本版限值报警实现
3. 回到一级「数据源管理 → 测试工程-34 → 新建工程」，名称填 `M6EnergyEvents`，类型选「报警工程」，目标选 `M6EnergyAlarm`。保存、发布，在节点添加该**数据源工程**并快速部署、启动。回到 `测试工程-5 → 数据源管理 → 新建`，选择 `M6EnergyEvents`，工程内名称填 `Events`。两行连接分别应为 `Rt → M6EnergyRT`、`Events → M6EnergyEvents`。

### 6　把 856 接上实时点，打开运行首页

1. 回到最初的 `EnergyOverviewM6` 编辑器。若新增的工程变量或数据源未出现在选择器，先保存当前页面，再从「页面管理」重新打开。单击「当前总功率」下的 **856**，核对对象名 `RichText100783467845196225606746`。数字和旁边的 kW 是两个控件，只改数字。
2. 单击画布空白，进入**页面**的「事件 → 基本 → 存在时」，打开脚本编辑器，确认函数栏显示 `onDisplaying()`。勾选启用，刷新时间间隔填 `1000` ms，把下面两行加入事件正文，保留已有业务语句，确定后保存页面。若属性栏仍显示富文本对象，重新选择画布再打开事件。

   ```js
   const meterCount = $System.ActivePowerRaw;
   RichText100783467845196225606746.setText(meterCount == null || meterCount === "" || !Number.isFinite(Number(meterCount)) ? "等待采集" : (Number(meterCount) / 10).toFixed(1));
   ```

3. 在编辑器左侧控件工具栏选「报警窗」，在能源总览页空白区域放置它。打开该报警窗的属性，窗口类型选「实时报警窗」，数据源选工程内的 `Events`。保留可看到发生、恢复和事件时间的列。原页面上的演示告警文字可用作版面参照，本轮以这个连接到事件源的窗口为取证对象。保存页面。
4. 回到客户端「页面管理」，核对 `EnergyOverviewM6` 带 PC 首页标记。若运行账号尚无此页访问权，从本客户端工程「安全对象 → 新建」建启用的访问策略，展开该页勾选「访问权限」，保存后在「关联用户」选择 `测试普通账号`。
5. 回客户端工程列表，勾选 `测试工程-5`，首次点「发布」，已发布的点「更新」。到节点找到或添加本场客户端 App，首次快速部署、启动；已有运行实例则对本场该实例停止、重新部署、启动。用普通账号打开 **http://192.0.2.1:本场客户端端口/** 。在实际运行首页核对数采监视 600 时「当前总功率」为 **60.0 kW**。

### 7　请观察员逐笔切换模拟电表

保持「数采 App 监视」和「运行客户端」两个标签打开。告诉观察员“监视和运行首页已打开，可以送数”。每次看到自己的监视值、质量、源时间和首页更新后，再通知观察员切下一笔。事件有传播时间，等待本笔结果再切值。

| 观察员送入 | 数采原始值 | 客户端功率 | 本次要看的报警结果 |
| --- | ---: | ---: | --- |
| 60 kW | 600 | 60.0 kW | 正常，建立基线 |
| 90 kW | 900 | 90.0 kW | 「园区总有功功率高」发生，记点名和发生时间 |
| 70 kW | 700 | 70.0 kW | 同一点恢复，记恢复时间 |
| 79 kW | 790 | 79.0 kW | 仍正常 |
| 80 kW | 800 | 80.0 kW | 等于高限时发生 |
| 76 kW | 760 | 76.0 kW | 原高报仍有效 |
| 75 kW | 750 | 75.0 kW | 等于恢复边界时恢复 |

若窗口只列活动报警，记录该行移除的时刻，再用事件记录核对对应的恢复时间。每个卡点留下**工程名、最后点的按钮、界面原话或截图**。观察员分开登记试验台输入、你的实际操作和 KF 运行结果。

## 本场自动复测

本场已部署，普通账号可直接打开[园区能源总览运行首页](http://192.0.2.1:23464/)。当前总功率和下方实时报警使用模拟电表，其余指标保留演示值。

在本场工作站的仓库根目录执行下方命令即可复跑。工作站需要能访问 3.32，本机 5179 试点网关、Chrome 和本仓库现有 Playwright 依赖需就绪。脚本从本机私有交接目录读取测试账号口令，并从运维资源定位该账号的数采与客户端实例。功率从 60 kW 开始，七档完成后恢复为 60 kW。每次单独生成结果目录并打印路径，内含七张画面截图和 `results.json`。

```sh
.toolchain/node-v24.19.0-darwin-arm64/bin/node docs/audits/kf-assistant-m6-20261120/run-energy-acceptance.mjs
```

现有 M6 电表通过私有目录中的 `meter-setpoint` 接受供数。若以后更换工作站，先按本页交接设备地址和普通账号。需要持续向客户端供数时，可在本场工作站单独启动下方工装，随后从另一终端复跑。端口空闲且未启动常驻电表时，复测脚本也可以自行启动一次性工装，完成后关闭自己启动的进程。

```sh
python3 -u docs/audits/kf-assistant-m6-20261120/meter.py --bind 192.0.2.2 --peer 192.0.2.1 --port 59510 --control-file dev/agent/.state/handoff-m6/meter-setpoint
```

用户的助手对话仍由用户操作。自动测试的步骤和卡点已记入本场观察记录。
