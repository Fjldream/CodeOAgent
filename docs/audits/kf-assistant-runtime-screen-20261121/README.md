## 普通账号如何使用

1. 在 Chrome 的扩展管理页选择“加载已解压的扩展程序”，指定 runtime-observer 目录。使用本机 5179 登录开发中心。
2. 在原生二维编辑器中单选目标文字控件。在另一个标签登录有权的目标 App，打开对应运行页，在扩展菜单中单击“KF 运行画面核对”。图标上的 KF 表示已关联。
3. 回到原生编辑器，展开助手的“工程工具”，选择“核对发布与运行画面”，点“查询”。也可以在原方案的当前对话提问“这次修改在这个 App 生效了吗？请分别核对保存、发布和运行显示。”
4. 核对编辑现场、保存文字、发布时间、目标实例、运行文件文字和控件显示的观察来源与时间。账号、页面、控件、实例不一致，观察超时，或运行标签缺少可见文字时，可以从助手看到尚缺的证据。动态控件的实际值与初始文字可以不同，进一步核对绑定和数据质量。

工具支持能唯一定位的原生二维富文本控件。运行浏览器用原始页面控件标识定位定义，再按唯一的原生对象取得可见的文字元素。此处验证单个控件实际显示。若要核对发布制品是否逐字节安装到节点，需要目标版本提供安装摘要。

## 自动复测

在完整工作区根目录使用 Node.js 24.12 以上的 24.x、已安装的 Chrome、Playwright 和本场普通账号口令文件。默认使用本地 M6 交接文件，可用 KF_M6_PASSWORD_FILE 指定。每轮使用独立浏览器并还原测试 App 的初始启停状态。

- `node docs/audits/kf-assistant-runtime-screen-20261121/recheck.mjs` 观察当前部署。
- 追加 `--pilot-ui` 在隔离的 Chrome 配置加载真实扩展，从 5179 的原生编辑器点选控件并验证真实工具请求和结果，结束时释放取得的编辑席位。
- 追加 `--publish-lab` 在指定独立客户端重建 18 基线、保存 27、更新发布并显式部署。已具备“保存 27、运行 18”时，可再追加 `--resume-baseline` 接续对照。
- `node --test dev/agent/test/*.test.ts` 包含错 App、错节点、账号、页面、控件、授权撤回、过期观察和缺安装摘要等回归。真实 OpenCode 配合隔离模型走自由提问、浏览器按需回执和历史撤权。KF 对象原名、显示文字和账号只在本机展开。
