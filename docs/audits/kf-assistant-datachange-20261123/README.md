## 运行实测

计数器位于处理函数入口。独立请求式探针只读取入口次数、最近的 InParam 和计算词典值。每窗同时读取数采点的值、质量与源时间，并从模拟设备的 Modbus 写入日志核对写请求数和值。下表的“写入”只列该观察窗内设备收到的写请求。坏质量期间的采样值按监视回读原样保留。

| 阶段 | 采样值 | 质量 | 进入次数（前 → 后） | 设备收到的写入 |
|---|---:|---:|---|---|
| 变为运行 | 1 | 192 | 6 → 7 | 1 |
| 保持运行 | 1 | 192 | 7 → 7 | 无 |
| 坏质量 | 1 | 0 | 7 → 7 | 无 |
| 恢复同值 | 1 | 192 | 7 → 7 | 无 |
| 变为停机 | 2 | 192 | 7 → 8 | 0 |
| 停机码变化 | 3 | 192 | 8 → 9 | 0 |
| 坏质量期间换值 | 3 | 0 | 9 → 9 | 无 |
| 恢复不同值 | 1 | 192 | 9 → 10 | 1 |

各次进入实收的参数均为字符串 `Global`。停机码从 2 变为 3 时，输入改变，分类依旧是 0，设备再次收到写 0。坏质量恢复时，是否再次触发取决于恢复后的值与词典保留值是否不同。

## 源码依据与范围

开发态的数据变化脚本列表和表头分别提供“生效”和“数据项”，保存操作把数据项与 JS 正文分别传给计算工程。运行态先筛选启用项，再为精确词典变量注册 setter，按 JavaScript 严格不等比较并派发事件。订阅包为字面 `Bad` 时，KIO 不给映射词典变量赋值。回调只得到来源，当前值从词典读取，输入质量由实时查询核对。开发态数据项 · 事件注册 · 事件参数 · 订阅处理

实机覆盖精确的 KIO 映射词典变量。内存词典变量的严格比较与分发由源码回归覆盖。通配符、直接连接表达式及其他驱动的质量编码尚待单独验收。首次同步本身可能触发，程序启动后应先核实词典已跟随输入。预跑时数采读值已变化而词典仍在初值，独立数采工程补建了变化转发，并通过快速部署同步。正式八窗在词典实际跟随 7 → 0 且设备有写回后开始计数。
