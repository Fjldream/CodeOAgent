# KF 开发助手跨轮任务记忆

这项能力用于同一开发人员在同一段对话中跨 KF 工程工作。助手保存用户明确说过的目标、适用人群和业务口径，用原话追溯每条决定。现场验收用同一普通账号、同一个人方案和同一段既有对话，客户端和计算工程均从 192.0.2.1 读取。

## 工作方式

- 每轮把新消息分句交给模型，结合当前可用的记忆以及上一轮已核验的追问，识别新增、改口和撤销。服务要求模型按顺序覆盖每个分句，本地校验编号、原话和修订关系。改口以现有条目为依据，明确给出替代值又撤销旧值时合并为一次替换。
- 模型生成和复核都能读取当前口径。工程变量、脚本或依赖的登记状态要用当前工程的只读工具确认。部署或运行需要相应层级的证据。
- SQLite 按对话、条目和来源回合保存。读取会复核账号对来源及依赖工程的权限。修订版在答复生成前通过事务记录口径，一个回合最多应用一次。答复阶段失败时已记录的用户决定仍然有效。
- 正式方案清单仍通过开发人员确认提议的现有流程更新。每段对话最多保存 32 条当前可用口径，每条原话最多 380 字。既有对话从新收到的消息开始积累，未做旧历史批量提取。

## 修订及验收边界

冻结候选 `761c7fde38c7` 通过 137 项本地回归，尚待新的真实模型独立验收。该版本在记忆提取阶段按业务相关性选择本轮条目，其他任务的决定仍可在同一对话的后续回合中被选回。生成和复核使用本轮相关条目，整表不再作为可直接粘贴的工具结果。替换时重建摘要标签；短答可参考权限仍然有效的上一条用户消息。若草稿遗漏了需要用户决定的问题，复核员可以拟定一条具体追问，再经单独复核交付。脚本菜单补查只有命中具体对象或模型确实查过菜单时才带入复核。

现场回合驱动使用普通账号的正常助手 API 和原对话，支持本组请求幂等续跑。修订后的受限转发将依赖登记、实测、失败和历史条数加入匿名投影。新的实测需单独指定 15 个合成问题、授权范围、模型、临时票据和本机输出目录。对受限转发和现场答复的修订未重跑已使用的独立题。
