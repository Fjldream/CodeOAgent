## 题源与故障条件

先复核冻结版哈希，再从已有仓储方案选择此前未验过的“库位状态异常累时”。工装固定一个账面为空的普通库位。当空位信号为 0、到位信号为 1 时，脚本应将原计数加 34，其他组合下已有计数应清零，连续一致且为零时应停写。工装以两秒为一个验收周期，沿用原规则每次加 34 的增量。选题与验收预期

为观察纠错，预先约定在 DeepSeek 首次提交工具参数后、冻结服务开始校验前，由普通账号只修改该独立工程结果点的说明。KF 计算助手的引用指纹包含点说明，修改会生成新的引用。现场回读确认点标识、点名、设备、寄存器、数据类型和权限一致。采样、计算规则与工具返回均沿用冻结版。模型接收脱敏题、匿名引用、KC 接口说明、自己的稿件及诊断。两次供应商提交已与 OpenCode 实收工具参数逐份核对。
