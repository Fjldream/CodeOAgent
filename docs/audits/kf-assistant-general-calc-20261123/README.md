# KF 助手通用实时数值脚本生成

2026-11-23 交付本机 M6。开发人员可以描述一个新的实时数值指标。助手先读工程与关联设备，模型提出公式，本机将公式绑定为两类 KF 脚本。产品代码没有双支路指标的名称、算法或两套测试点名。日冻结表底差仍保留原有入口。

## 助手怎样工作

| 环节 | 当前能力 | 判断依据 |
| --- | --- | --- |
| 找输入输出 | 从当前计算工程读取数据源和数据词典；在客户端入口读取连接和工程变量。按实时源的工程引用查有权数采工程，展示设备、点、转换类型、读写属性、已匹配的变量及匿名引用。原对话可显式沿最近计算回执定位计算工程。 | 对关联工程重新验权；精确核对工程内别名、数据源和点名。重复点名、字符串类型和只读输出不能参与相应数值写回。 |
| 判断是否需要提问 | 用户提问或同一工程最近的提问中指名的点、描述或变量在本机匹配；模型收到引用及匹配位置。缺少会改变计算的口径时，模型可选择追问分母、输入、单位、舍入、时间窗等缺项。 | 在独立对话副本先给出分母未知的需求，实际答复为“请确认这个比率的分母或比较基准。”下一轮只补分母，模型沿用前一轮的输入和输出角色生成两份正文。追问 · 续答 |
| 写两类脚本 | 模型组合算术、比较、条件表达式及绝对值、最值、开方、舍入等运算；本机解析表达式，仅接受支持的语法、函数和当前工程引用。周期宿主读点并写结果和可选有效标志；请求宿主读取同一组输入，经 OutParam 与 endResponse(RequestID) 返回。 | 再读配置后检查权限、输入可读、输出可写、物理点重合、结果类型、KF 语法与显式引用。候选生成只读，保存与发布由开发人员或独立验收工装执行。 |
| 对照实际结果 | 用已部署的独立 App 分别取证。每组输入核对四个 KF 点的值、质量、源时间，模拟设备收到的两只输出寄存器，以及 HTTP 实际业务回包。 | Center 读回正文逐字匹配助手输出。原 M6 对话另关联了 A 工程三组周期监视和三笔浏览器 HAR 回包。 |

运行约定为逐笔输入须有有效数值、质量码 192 和可解析的源时间。时效缺省 15 秒，可在公式参数指定；无时区的设备时间需要部署方已核实的源时区偏移。周期算不出时保留结果，可选标志置 0；请求返回 value=null 及状态。输出须适配保存的转换类型，整型结果不能包含小数。若现场需要其他异常契约，应另行确认支持范围。多源点按连接分别读取，不能据此推断所有源同步采样。写回和数采监视由 KF 提供，进程已加载正文哈希仍未知。

## 换工程实测

| | 独立工程 A | 独立工程 B |
| --- | --- | --- |
| 计算 App／工程连接别名 | 测试工程-31／FlowA | 测试工程-32／FlowB |
| 独立设备 | SplitFeed | TwinFeed |
| 两路输入 | LineLeft、LineRight | BranchBlue、BranchGold |
| 数值输出／有效标志 | BalanceIndex／SampleFlag | DeltaScore／Usable |
| 模型取材和实机回执 | 模型调用及绑定 · 逐笔回执 | 模型调用及绑定 · 逐笔回执 |
| 实际交付正文 | 周期 · 请求 | 周期 · 请求 |

两次输入同一句业务描述，模型各自调用工程清单和公式编译工具。按开发人员授权，选择总流量作分母，公式为 round(100 × abs(左 − 右) / (左 + 右))。两套使用独立的工程、部署实例和模拟设备。对于非负无符号输入，两次模型给出的分母有效条件分别为大于零和不等于零。普通账号身份类型为 03。

| 步骤 | 左／右 | 预期 | 两套 App 的写回与请求 |
| --- | --- | --- | --- |
| 正常 | 60／40 | 20 | 数值 20，标志 1；请求 value=20 |
| 相等 | 10／10 | 0 | 数值 0，标志 1；请求 value=0 |
| 单侧为零 | 0／100 | 100 | 数值 100，标志 1；请求 value=100 |
| 右侧较大 | 33／67 | 34 | 数值 34，标志 1；请求 value=34 |
| 非整数比率 | 50／49 | 1 | 数值 1，标志 1；请求 value=1 |
| 分母为零 | 0／0 | 无效 | 保留 1，标志 0；请求 value=null、status=condition_failed |
| 恢复及交换方向 | 40／60 | 20 | 数值 20，标志 1；请求 value=20 |

14 笔独立请求均为 HTTP 200，现场每个监视样本质量码均为 192。坏质量、过期、结果越界、小数写整型、撤权和旧工程引用由回归覆盖。现场模拟帧使用相同工程单位。迁移验证覆盖两套实时源的无状态数值公式；历史窗口、跨周期状态、数据库查询、事件触发、一般 JavaScript 和任意 Python 不在此次生成验收范围。

## 验收与续用

- 在计算工程或原客户端打开助手，先问“请核对当前工程的输入、可写结果点和已有变量”。可以用设备点名、工程变量名或清单中的匿名引用说明用途。显式指定“沿用本段对话最近验收的计算 App”即可从其他入口继续。当前案例保留最近的 A 工程回执。
- 当前助手清单读取至多 24 条连接，公式输入最多 12 个，从清单前 48 个可展示点取材。未列出的项须继续核对；编辑草稿、发布版本和运行值是不同证据层。
- 云端验证使用真实 OpenCode、deepseek-v4-flash 和普通 KF 账号，在原对话数据库的隔离副本操作。外发代理只传本次虚构需求、匿名引用、读写属性、匹配位置及公式工具说明；正式工程名、点名、历史、正文和运行读数留在本机。验证测的是限定计算工具集内的生成与澄清，未据此评估全部工具下任意自然语言的选择准确率。
- 云端工具与续聊验证 · 现场验算 · 原段对话取证 · 原入口复验 · 六笔原对话取证编号 · 编译及权限回归
- 本机两组专用模拟器的输入、预期和实例标识保存在 dev/agent/.state/pilots/energy-20261120/general-formula/A 和 B。复测时给 field.mjs 传入对应目录，会切换专用模拟输入并恢复 60／40。工作站重启后可用 simulator.py 指定相应 meter.json、工作站测试地址和模拟端口（A 为 59524、B 为 59525）。服务默认仅对测试节点及本机接受模拟请求。
