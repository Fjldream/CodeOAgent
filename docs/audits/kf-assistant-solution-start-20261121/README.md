# 方案起步 · 普通账号验收

2026-11-21 15:20（北京时间），从本机 5179 开发中心的通用入口以 M6 专用普通账号操作，后端使用 192.0.2.1。已有个人方案，未打开业务工程。在「工程工具 → 方案起步」中取得以下结果。

首次复查发现默认组的大量无权行用尽了检查预算。修复后先略过明确无权的行，再轮流从各可见分组取候选；显示名称前复核本人读取权限。专项测试同时覆盖原生列表缺少权限标志、标志过期、同名工程、无分组候选、目录不可用以及读回历史时已撤权。对同名工程保留各自工程标识。候选目录和方案步骤都不能证明项目已经发布、部署或能用在当前业务。

自由提问的自动回归使用真实 OpenCode、本机脚本化模型服务以及模拟 KF 目录。它从通用入口发送新设备接入问题，通过 MCP 调用 plan_solution，核对最终答复、候选名称只在本机展开、撤权后隐藏旧答复。此回归验证调用链。上表的界面验收连接实际 KF，走本机只读工具；本轮未向云模型发送测试问题。切换试点版本保留了原对话 13 轮。陌生开发人员独立操作的完成率仍待 M6 人工验收。

- 复测开发中心操作用 check-pilot.mjs。在工作区根目录使用 Node 24、已安装的 Chrome/Playwright 和现有 M6 普通账号本地环境运行。脚本只打印匿名统计，不写工程或个人方案。
- 流程与目录回归覆盖新设备、已有点、已有源、纯静态、关系或历史报表、已有报警事件及 3D 入口；对话集成测试覆盖真实 OpenCode 调用和历史权限复核。
- 工程分类、中文入口和创建字段对应开发中心菜单、中文文案、数采新建表单。客户端发布前查有效默认页的实现见客户端工程列表。
