# 二维控件绑定与运行旧值核对

## 在原对话继续

用本场普通账号进入本机 M6 开发中心。在「客户端管理 → 测试工程-8」选择测试工程，进入「页面管理」，单击页面名称，在新标签里单选目标控件。打开「开发助手」，切回「园区能源总览 → 第一段对话」。可以问“请核对当前控件绑定了哪个工程变量。带我找到对应的页面事件，并说明在哪里验证它已经生效。”也可以使用「工程工具 → 二维控件绑定 → 查询」。

| 客户动作 | 操作和验证 |
| --- | --- |
| 定位控件 | 单选后核对浮窗底部的页面名及控件名。温度文本核对 `setText`，Element UI 按钮核对标题属性 `Caption`。按钮的点击动作有独立事件。 |
| 确认变量 | 在「二维控件绑定」查询。逐项对照“工程变量 ← 客户端连接别名 / 采集点 · 设备”。有多个候选就按设备、来源和点名选定，输入完整工程变量名重查。若没有候选，在「查采集点与变量映射」检查来源、权限、映射和订阅。 |
| 配置动态显示 | 先记下选中控件和变量。单击画布空白处，打开右侧「连接 → 基本 → 存在时」，在事件行点「…」。单击脚本工具栏的「变量」，在工程变量所属分组选择变量，点「确定」。无已有绑定时，把刚插入的引用替换为助手给出的完整语句，放在原脚本末尾。已有绑定时修改原来的写入语句。复核刷新间隔，启用「存在时」，点「确认」，点击页面工具栏保存。 |
| 回读保存结果 | 重新单选原控件，再查询「二维控件绑定」。结果应显示控件名、事件、工程变量和刷新间隔。其他脚本也写这个属性、同名或选区含多个控件时，按提示先核对原生脚本或重新单选。 |
| 核对运行 | 用同一普通账号打开对应客户端 App 的运行页。在 Chrome 点击「KF 运行画面核对」关联这个标签，再到开发助手选「核对发布与运行画面 → 查询」。记录 App 页面文件、运行标签已加载的事件与 Center 的比对，以及实际显示和采样时间。若刚更新扩展，从 Chrome 扩展管理页重新加载，再在运行页关联一次。 |

原生脚本编辑器在本次测试分辨率下遮住了底部「确认」的鼠标点击区域。用键盘 Tab 将焦点移到「确认」，按 Enter 可以提交。最初单选按钮与最终查询所用的名称相同，编辑器实例编号会随打开变化。助手按当前工程、当前页面、控件类型和唯一名称复核，编号与名称冲突或有重名时停止。

## 2026 年 11 月 22 日现场

本机试点连接 192.0.2.1，账号 `测试普通账号`，KF 账号类型 03。以下两处均从真实编辑器选区开始，按工具返回的代码、原生变量选择器和保存入口配置，再读回工程文件。两个测试副本保留本次绑定。

| 客户端工程 / 页面 | 原生选区与使用的变量 | 已保存结果 |
| --- | --- | --- |
| 测试工程-19 / ProbeScreen | 温度文本 `TempValue1121`，选择 `TempDisplay1121 ← TempRT / ProbeTemp1121 · NorthRTD` | 启用的「存在时」通过 `TempValue1121.setText(…)` 读取该变量，间隔 1000 ms。初始文字为 `27`。 |
| 测试工程-5 / EnergyOverviewM6 | 初始标题为「查看运行说明」的按钮，选择 `ActivePowerRaw ← Rt / ActivePowerRaw · Meter01` | 启用的「存在时」给按钮的 `Caption` 赋值。已有页面脚本保留。保存前后对照了园区页 36 个控件的名称、类型编号、静态文字及各自事件列表。这里展示原始功率点；若要显示 kW，还需按点表换算。 |

**同页切换选区。** 在园区页重新打开助手，先选「查看运行说明」，浮窗列出已保存绑定和改绑入口。在同一编辑标签将浮窗最小化，单选仍未绑定的「设备监测」后恢复浮窗。原对话标题保持「园区能源总览 / 第一段对话」，此前选区的绑定结果已清除。再次查询，浮窗显示这个按钮自己的 Caption 赋值语句、工程变量 ActivePowerRaw、变量选择器和勾选事件的步骤。后一个按钮保留未绑定，适合从原对话复验首次指导。

**温度页旧值。** 保留原先部署的温度测试 App，临时启动，登录它自己的运行页。北京时间 10:16:52 和最终版本复测的 10:20:46，M6 浮窗均实际读到文本 `27`，目标 App 页面文件和运行标签已加载的「存在时」均与 Center 保存版本不同。此时可以先查该工程的发布记录与目标 App 部署。若 App 文件已匹配而浏览器所加载的事件仍旧，重新打开运行页再取样。比对对象是这个页面的周期事件；整包安装版本和温度探头的实时工程值需要各自的证据。测试结束后，回读温度 App 恢复为初始停止状态。

本轮两处绑定在保存层验收；旧版本显示在温度测试 App 实机验收。按钮的新功率显示尚待发布部署后以已知输入验证。用户原对话的 13 轮及方案归属在试点升级前后校验一致。自由提问采用真实 OpenCode 配合本地测试模型回归，两个控件均按本轮工具输出实名结果。本轮 51 项回归、TypeScript 检查与前端生产构建通过。自动审批因外发现场选区及工具资料的授权范围拦下了额外的 DeepSeek 实测，现场云模型答复单独留待用户验收。

## 可重复验证

- 工作区使用 Node.js 24 运行 `node --test dev/agent/test/*.test.ts`。覆盖两类控件的指导和回读、按钮临时编号与原生存储格式、变量和控件重名、订阅关闭、撤权、重复写入以及旧标签和缺少版本回执。
- 本机 M6 已启动并连接现场时，从仓库根运行 `node docs/audits/kf-assistant-control-binding-20261122/check-pilot.mjs --pilot --observe-test-app`。需要已安装的 Chrome、工作区 Playwright 和本场普通账号口令文件，可用环境变量 `KF_M6_PASSWORD_FILE` 指定。脚本从两个普通开发入口进入，打开原生新标签，在温度案例临时启动专用客户端并在退出时恢复。
- 已有这两个测试副本但还未绑定时，`--save-test-bindings` 会在原生界面保存，保存前备份页面 JSON 到当前用户的临时目录。已有唯一目标绑定时跳过写入。若运行 App 此后已更新部署，旧值用例应记录新基线；复测脚本会在现场与预期不符时报告差异。
