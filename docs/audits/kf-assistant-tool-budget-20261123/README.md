# 计算助手工具修订与周期写回盲验

**冻结版 3d3182373d67 未通过端到端验收。** 普通开发账号实际收到了被退回的原因。模型交了两次相同的 JS，工程中保存的周期脚本数为 0。没有可核对的计算 App 写回，M6 保持原试点版本。

## 本次产品改动

- 运行接口查询按单轮、函数族与规范化符号复用结果，并发相同查询共用一次执行。独立对话重新取材。模型调用和工程查询分别计数，纠正供应商输出也计入模型请求上限。
- 网关按本轮实际工具目录拼合并检查供应商返回的流式函数名。已关闭工具或整批重复的运行接口查询在送给 OpenCode 前拦下，允许一次纠正，继续违规即停止。已开放的工具在同批多次调用时，后一个仍可能因前一个耗尽额度而被本机拒绝。
- 计算环境按可访问的连接类型携带常用读写接口说明，按函数族查询也会返回已核实的用法。对照 Node 中的全局包装、输入检查和 HTTP 实现，补齐了 KIO 和 SQL 的等待式、回调式写接口。KIO 写回的 HTTP 实现会清空错误数组，成功总码为 0，必须独立回读目标值。SQL 写入默认超时 3000 毫秒，返回码不含影响行数。两类接口均可能返回非零错误码。超时后应先确认目标状态。
- 工作区与冻结副本逐文件哈希一致，运行态注册索引复核通过。修订未引入任何设备业务模板。冻结清单

## 诊断与下次验收

候选用五个只初始化一次的 var 声明承载已授权匿名引用。冻结版校验器只解析 const 初始化别名。离线复核用同一冻结校验器、同一份候选与同一批绑定，只替换这五个声明关键字，三条引用错误全部消失。这次对照仅用于定位，未保存或运行修改稿。候选还把质量码 0 视为良好；即使引用核验通过，异常质量分支也需要独立验证。本机对照

下一轮应基于绑定作用域和赋值路径解析能证明稳定的别名，并在诊断中指出具体表达式和可修正的原因。应验证同名遮蔽、重赋值、连接错配和输出越权仍能被挡住。运行接口资料应明确采样字段和质量的有效条件，并用跨领域测试覆盖异常质量下是否停写。修改后另行冻结，再以新题核对正式对话、保存正文及正常、异常、恢复写回。
