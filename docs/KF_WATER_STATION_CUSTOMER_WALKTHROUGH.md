# 案例 01　供水站出口压力监控

本例操作环境为 KF 3.6 开发中心，地址为 [192.0.2.1](https://192.0.2.1/)，节点名为 `test`。目标是在运行客户端读到出口压力、最近五次采样的均值，并看到高报发生和恢复。本手册将普通账号本轮实际操作和以前的运行结果分别标明。复做时请为工程使用自己的唯一名称，全文引用处随之替换。

**2026-11-20 实测。** 管理员配好案例分组后，普通账号完成了六个 App 的绑定和发布部署。节点上先读到稳定的 500 kPa 和五次均压 500.0 kPa，接入测试寄存器后，运行首页显示 0 kPa、均压 0.0 kPa，两端的计算截止时间一致。第 7 节留有 600 kPa 高报、560 kPa 恢复，以及两次滑动均压 520.0、536.0 kPa 的数采和客户端实测记录。第 8 节给出开发助手应怎样根据客户提供的证据进行指导。

## 1　登录并确认操作身份

1. 在浏览器打开开发中心，使用分配给自己的普通用户账号登录。本轮专用账号为 `测试普通账号`。现场的账号由管理员在「用户管理 → 用户系统」选中用户分组后，通过「新建用户」建立，用户类型选「普通用户」。
2. 登录后核对右上角账号。左侧应能找到数采、数据源、计算、报警和客户端五类工程管理入口。本轮普通账号能看到这五类入口，侧栏没有「用户管理」和「权限管理」。
3. 点「数采管理」展开树，再点它下面的「默认工程组」。右侧出现带「新建工程」「发布」按钮的工程列表。其他管理分类下也有同名分组，操作时先看上一级分类。

### 建两个业务点

1. 在工程左侧点「数采变量」，点工具栏的「新建」。弹窗标题为「新建变量」。先选「关联设备」，再选「寄存器名称」，最后选「寄存器数据类型」。后两项的可选值取决于前一步。
2. 分别按下表建点，每次点「确定」并等到列表出现该行。采集频率均填 `1000` ms，转换模式保持「无」。

### 配置实时转发

点工程里的「转发配置 → 新建」。在「新建数据转发」中，第一项「转发类型」为 `WellinTech-MQTT`。保留「亚控主题」、连接模式「匿名无加密」。本例「提供商」填 `WaterGuideMQ`，「转发地址」填 `127.0.0.1:23883`。在第二个「转发类型」选「间隔转发」，周期填 `1000` ms，心跳填 `60` 秒，重连填 `3` 秒，服务质量选 `0`。点「确定」。本轮列表已读回转发名称 `WellinTech-MQTT`、地址、心跳和重连间隔。连接是否真正传值须在后续订阅端核对。

3. 点「app管理 → 添加」，在「添加APP」弹窗右侧点「名称 → 选择」。在「选择工程」左树展开「采集工程」，点其「默认工程组」，在右边点 `WaterIOGuide1120`，再点子弹窗的「确定」。回到「添加APP」，端口填 `23310`，点「确定」。本轮在节点列表读回「采集工程 / 23310 / 未部署 / 未运行」，并出现「监视(23310)」入口。这个状态只表示运行实例已登记。

## 5　建立计算、报警和客户端空工程

### 配置五次均压的周期脚本

1. 在计算工程左树点「脚本」左侧的小三角，展开后选「周期性脚本」。右侧应显示「周期性脚本列表」。点「新建脚本」。
2. 「脚本名称」填 `PressureAverage`，触发模式选「固定周期触发」，时间间隔填 `1`，单位改为「分钟」，执行次数填 `-1`，保留「结束」未勾选。将「开始」设为节点本地时间的第 30 秒，早于预计启动时刻。本轮保存的是 `2026-11-20 00:00:30`。点「确定」，列表应出现 `PressureAverage`，周期为「固定周期触发」。现场触发表单
3. **双击脚本行**进入「脚本编辑器」。在预置的 `//周期执行脚本` 注释下一行，贴入案例设计第 3 节的第一个 JavaScript 代码块。这个版本的该编辑区接收脚本正文。点编辑器工具栏的保存图标，等到「PressureAverage 脚本保存成功」。本轮看到保存成功并核对了末尾的写回和状态复位语句。保存后编辑器
4. 运行此脚本前，在**计算工程内部**选「数据源管理 → 新建」。弹窗中「数据源」选本例实时数据源，「名称」填 `Rt`。此名须与脚本第一行的数据源别名一致。本轮保存后读回 `Rt → 测试工程-1`。返回计算工程列表，勾选工程点「发布」，13:15:18 显示「已发布」。到运维中心按第 3 节选择「计算工程 → 默认工程组 → 测试工程-4」，端口填 `23311`，快速部署后点「启动」。在数采的「监视(23310)」筛选 `P_` 并按回车，结果点已从空值变为带新截止时间的文本。例如 13:24:32 读到 `WAIT 4/5 | 2026-11-20T05:24:30.079Z`、质量 192。写回已到达数采；有效五次均值按第 7 节核对。计算工程内部的实时源 · 计算 App 节点状态

## 8　开发助手怎样带客户完成这一例

客户说「我要监控供水站压力」时，助手先问清压力点、单位、均压窗口、报警边界和运行用户。本例的回答是出口压力 `P_OUT`、kPa、每分钟取一次且最近五个有效分钟、到 600 高报、低于 600 恢复。若客户说的是五秒均压或要求掉电保留窗口，先重新确定计算方案。

| 客户当前停在哪一步 | 助手给出的下一条指引 | 客户怎样证明这一步通过 | 检查不通过时先查什么 |
| --- | --- | --- | --- |
| 登录后找不到案例组 | 请展开「数据源管理」，提供当前账号和可见分组名称。 | 普通账号看到并能打开目标组。 | 由管理员核对案例角色与分组勾选，再以普通账号重新登录，见第 4 节。 |
| 已建采集点，压力一直是 500 | 请在节点数采 App 的「监视」筛选 `P_OUT`，按回车，隔十秒再读一次。 | 两次记录同时有数值、质量 192，且源时间推进。 | 若显示两个破折号，先确认监视窗口内已执行筛选，再看设备、运行节点、地址和端口。 |
| 点能采到，但均压显示等待 | 请确认计算工程内的别名 `Rt` 指到本例实时源，比较结果寄存器的文本与截止时间。 | 结果出现本轮新的 `AVG5` 文本，五个输入可独立算出同一数值。 | `WAIT n/5` 且时间推进表示脚本在写回，去查缺少的有效分钟。时间不动时先核对计算 App、脚本周期、输入质量和结果点读写属性。 |
| 到阈值，画面还没看到报警 | 请先读同一时刻 `P_OUT`，再打开「报警属性」核对高限和报警文本，最后看运行画面的报警行。 | 同一变量达到 600 时出现高报，随后低于 600 时出现恢复，事件工程属于本例。恢复行的「报警值」保留发生值 600，当前 560 从压力控件读取，「事件时间」给出恢复时刻。 | 依次核对报警工程的 `Rt`、词典和转发 Broker、事件源目标、客户端 `Events` 别名。 |
| 可以编辑画面，登录后提示无权限或只显示等待 | 请确认默认首页、`StationViewer` 的页面权限和关联用户，再查看部署版本。 | 同一普通账号打开首页，压力、均压文本与数采同笔数据一致，报警来自正确工程。 | 核对工程变量同名映射、页面脚本的 `$System` 名称、更新发布和节点重新部署。 |

助手引用客户手册时应给出当前这一步的按钮、需要客户提供的字段、以及通过条件。用户给出截图、监视读数或授权只读查询后，才能把「等待核对」改为「通过」。看到「已部署」只推进部署步骤，业务签收还需要真实读数。修改权限、发布、启停和模拟送值由客户在自己的环境里操作。本例的写寄存器脚本是测试台附件，助手指导生产工程时应先询问客户能否提供独立模拟输入。

**用这份案例验收助手。** 给助手一个新的模拟客户，只提供需求和当前界面。逐轮提供上表所列证据，其中一轮故意给旧时间的均压截图。验收时看它能否定位缺失证据、解释下一步、给出正确脚本，并在收到新的运行读数后才确认完成。知识检索可先读本手册和平台函数说明。后续有只读 MCP 时，可用同样的判断核对工程关联、发布版本和点值。均压的复算、界限判断及时间换算可以用确定性函数完成。此项是开发助手产品的测试设计，产品实测另行记录。
