# KF 开发助手工程联调记录

2026-11-20，北京时间。本机开发中心与助手接入 192.0.2.1，使用普通开发账号 `测试普通账号`。现场新增独立计算工程及 App `KFGuideMeanLab1120`、请求式脚本 `GuideFiveMean`，并在案例客户端工程中新建测试报表 `M2CellReview1120`。部署、启动和业务测试由联调人员使用普通账号进行。助手提供查询、静态检查和可复制模板。个人方案条目仍由开发人员确认后生效。

## 从开发态复核

1. 登录本机开发中心，在顶栏打开 **开发助手**，从 **历史** 选择个人方案，或新建一个。在数采、报警、计算、客户端的工程列表点工程名；在数据源管理展开 **WaterGuide1120** 并单选 **测试工程-1**。点 **核对已保存配置**，逐项核对数采设备 `SimPLC`、报警工程连接 `Rt`、周期脚本 `PressureAverage`、客户端页面 `StationPressure` 和所选数据源的类型。切换对象后重新查询。
2. 在 **客户端管理 → 测试工程-2 → 页面管理** 点 **StationPressure**，在打开的新标签单选压力文字 **PressureValue**。打开助手的 **工程工具 → 追踪上游 → 查询**。路径为 `PressureValue → Rt → 测试工程-1 / P_OUT → WaterIOGuide1120 / SimPLC / P_OUT（地址 1）`。选中压力文字得到一个输入；页面上另一个均压控件用的点为 `P_AVG5_TEXT`。
3. 改选报警窗 **StationAlarms**。同一工具读到 `Events → WaterEventsGuide1120 → 测试工程-3`，末项来自事件数据源中配置的报警工程名称。实际报警发生、恢复及事件时间由运行客户端核对。
4. 从 **计算管理 → 测试工程-4 → 周期性脚本 → PressureAverage** 打开脚本，点 **询问此脚本 → 核对已保存配置**。回到压力控件，沿用同一方案，另开一段对话，选 **反查本方案**。现场能定位到均压脚本读取同一个 `P_OUT`。反查按当前权限重新读，最多复核 16 个该方案曾访问的控件、页面或脚本。动态点名或多个候选须另行定位。
5. 在客户端 **报表库** 打开 **M2CellReview1120**，先点 A1，再点 B4 并核对配置。助手依次定位到 **Sheet1 / A1** 与 **Sheet1 / B4**。现场这两个单元格没有保存的数据集绑定；使用带绑定的测试样本另行检验了字段映射。在 **3D 资源管理** 打开 **default.json**，原生新标签与助手都指向此场景；本轮核对到场景登记，模型内部对象及渲染效果仍需在 3D 画面查看。
6. 在同一脚本打开两个开发态标签，仅在 A 修改草稿。分别点 **核对已保存配置**，A 显示编辑文本与 Center 读回不同，B 保持原文。在保存失败用例，浏览器在提交抵达服务端前返回 503，原工程脚本保持原文。助手再读时仍报告差异。正常保存请求式示例时，KF 会补文末空行，助手将这种情况显示为“仅换行格式或文末空行不同”。
7. 选择 **工程工具 → 部署与进程**。客户端案例实例回报 **已部署、运行中**。核对目标节点与 App 标识后，再到运行客户端查业务输出。单个部署状态、发布时间或查询时间都不能充当脚本执行回执。

8. 在 **数采管理 → WaterIOGuide1120 → 开发助手 → 工程工具** 选 **读取实时点值**，点 **查询** 加载本账号有权的实例，再选择 **WaterIOGuide1120**、输入完整点名 **P_OUT** 并查询。浏览器等待网关确认监视连接后订阅一个点，须收到点名、值、质量和源时间才展示；退出监视即断开。17:53 网关确认了连接与订阅，目标数采 App 的进程状态为 0（界面“未运行”），本次未收到点值。该账号没有其他运行中的数采实例。已用固定回执单测核验零值、坏质量、时戳、取消和选错点的处理。正向现场点值仍待运行数据源可用时复核。
9. 17:55 使用同一普通账号打开实际运行客户端的 **StationPressure**。画面显示“出口压力  0 kPa”“五次均压  等待计算”及“实时压力报警”，当时未看到恢复事件。缺少同时间的有效数采样本，这个 0 仅登记为画面显示值。此前客户手册里的 600/560 和均压结果带有各自的观察时间。

| 17:38 现场读取 | 证据编号 | 可复核的内容 |
| --- | --- | --- |
| 二维压力控件上游 | `匿名标识-1` | 控件、实时连接、数采点及地址 |
| 客户端报警窗上游 | `匿名标识-2` | 事件源及其配置的报警工程名 |

证据编号标识该次查询。重新查询会产生新的编号及读取时间。

## 新脚本进入 KF 后实际做了什么

在独立计算工程创建 **请求式计算脚本 → GuideFiveMean**。从助手的 **工程工具 → 可复制脚本示例** 取得请求式正文，在 KF 脚本编辑器中粘贴、保存，再点 **核对已保存配置**。点 **静态检查当前脚本** 可检查语法、宿主及显式读写参数。请求式示例通过 `InParam.samples` 取五个样本，写入 `OutParam`，以 `endResponse(RequestID)` 结束。周期示例按有效分钟维护独立窗口，使用的是另一种宿主。

普通账号发布工程，在节点 **test** 创建独立 App，部署并启动。在该实例的 23462 端口调用 `/GuideFiveMean`。每一笔都从目标进程取得 JSON 回包。

| 输入样本值 | 质量 | 实际回包 |
| --- | --- | --- |
| 480、500、520、540、560 | 全部 192 | `{"status":"ok","mean":520}` |
| 500、520、540、560、560 | 全部 192 | `{"status":"ok","mean":536}` |
| 480、500、520 | 全部 192 | `{"status":"need_five_samples"}` |
| 480、500、520、540、560 | 末个样本为 0，其余 192 | `{"status":"bad_sample"}` |

**A/B 的实际时序。** A 的校验请求返回均值 520。B 在显式传入 `verifyBuild:true` 时额外返回 `probe:"B"`。保存 B 并从 Center 读回后，目标实例仍返回 A 的响应；更新发布后立即再测仍为 A。界面显示的发布版本两次均为 `1.0.0.1`。后续提交的停机命令在该次轮询窗口内一直报告处理中。随后从目标实例读到了 B 的探针，又复测了上表四个分支。记录可以确定 B 已实际响应；具体切换时刻、触发切换的命令及安装制品哈希都缺少对应回执。

## 助手可以引用哪些依据

| 用户正在做什么 | 查询与证据 | 范围 |
| --- | --- | --- |
| 确定当前入口或寻找对象 | `get_context`、`find_objects`、`read_object` | 按发问时的工程、标签页及选区读。编辑稿比较保存指纹；只有显式检查时才把稿件正文交给本机服务。 |
| 询问下一步怎么操作 | `lookup_reference`、九类操作指引、供水站六步流程 | 按当前模块回答。供水站有历史现场记录，其他客户工程须取自身证据。 |
| 查上下游、评估改动 | `trace_refs`、个人方案引用索引 | 分开标注读取、写回和事件源。账号对目标对象失去权限后须重新校验。 |
| 判断部署及运行 | `read_runtime`、节点状态、目标实例测试回执 | 同一工程可以有多个 App，节点与进程各自报告状态。数采工具的单点监视限明确选择的有权实例。业务回包作为单独证据登记。 |
| 编写计算脚本 | `validate_candidate`、分宿主模板、固定输入输出 | 静态检查、样例复算与实际 KF 运行各有结果。OpenCode 两轮使用同一原生会话和本机模型协议测试端点调用只读 MCP，获取两份真实 KF 对象证据。本轮没有外发模型请求。 |

**工程回归。** 使用真实 OpenCode 通过本机测试模型端点逐项调用表中的七个 MCP。现场 KF 数据由普通账号读回，模型侧只接收对应的查询投影；追踪压力控件时，本地最终答复包含 SimPLC 与点名。另做两轮同原生会话续聊，第二轮引用两次证据。12 项自动化回归、TypeScript 检查及前端生产构建通过。解压包使用与锁文件匹配的本机依赖，普通账号成功打开五类工程并核对对象。共享 Center 的助手入口仍待现场试点。

供水站普通账号早前在运行首页验证过 600 kPa 高报、560 kPa 恢复和两组均压。本次工程联调复用其已保存工程验证助手，并在独立 App 执行新脚本。历史报警的现场步骤与截图在完整工作区的《供水站压力监控客户操作手册》中。下一轮独立验收仍包括陌生工程的设备接入任务、真实双节点对照，以及按用户安排另行组织的 M7 盲测。各阶段以实施计划第 8 节为准。

## 18 时现场补验 · 从工程配置核对到实际输出

同一天用普通开发账号连接 192.0.2.1。以下记录接续上文 17 时的观察。时间使用北京时间，画面内以 `Z` 结尾的是计算脚本写入的 UTC 时间。

### 数采与运行客户端

1. 在运行管理中核对案例数采实例 **WaterIOGuide1120**。唯一已启用设备 **SimPLC** 指向该节点自身的模拟器。测试前该实例已部署、已停止。操作员仅为本次采样启动这个实例。
2. 在本机开发中心打开 **数采管理 → WaterIOGuide1120 → 开发助手 → 工程工具 → 读取实时点值**。点 **查询**，选同名实例，分别输入 `P_OUT` 和 `P_AVG5_TEXT`。18:04:35 读到出口压力 500，质量 192。随后均压点返回 `WAIT 1/5`。这时窗口刚开始累积。
3. 保持模拟值，等满五个有效分钟样本。18:08:33，在真实运行客户端 **StationPressure** 读到“出口压力 500 kPa”和“五次均压 AVG5=500.0 kPa | 2026-11-20T10:08:30.117Z”。再读助手，原始点仍为 500，质量 192，源时间 18:08:38.021。均压点返回相同的值和计算截止时间，质量 192，源时间 18:08:39.024。比较时分别保留采样时间、脚本截止时间和画面观察时间。
4. 采样结束后停止该数采实例，复查进程状态回到 0。供水站客户端、计算、报警和独立计算测试 App 均为运行中。本轮使用模拟器原有压力，600 kPa 高报和 560 kPa 恢复沿用客户手册中有时间戳的历史验收。

### 报表 B4、自定义数据集与请求式计算

1. 在 **计算管理 → KFGuideMeanLab1120 → 请求式计算脚本** 新建 `GuideReportMean`。点 **询问此脚本 → 工程工具 → 报表数据集脚本示例 → 查询**，复制正文到编辑器，保存后点 **核对已保存配置**。普通开发人员更新发布此独立工程，使用该工程的运行 App 验算。
2. 在 **客户端管理 → 测试工程-2 → 报表库 → 默认报表组 → M2CellReview1120**，在“数据集管理”新增或编辑自定义数据集 `MeanReview1120`。成员填 `mean`，计算 App 选 `KFGuideMeanLab1120`，脚本选 `GuideReportMean`。“查询条件”可直接复制助手给出的 JSON，也可使用下面这一笔串行验算样本。

```json
{"RequestType":"normal","InParam":{"samples":[{"V":480,"Q":192},{"V":500,"Q":192},{"V":520,"Q":192},{"V":540,"Q":192},{"V":560,"Q":192}]}}
```

3. 选择 **Sheet1 → B4 → 单元格属性**，设置数据集为 `MeanReview1120`、字段为 `mean`。在编辑器保存报表并确认，等“保存成功”。选 B4 点 **询问当前单元格 → 核对已保存配置**，再去 **工程工具 → 追踪上游 → 查询**。最终保存路径为 **Sheet1 / B4 → MeanReview1120 / mean → KFGuideMeanLab1120 / GuideReportMean**。18:24 的证据编号为 `匿名标识-5`。助手使用当前账号，依次复核报表、数据集标识、字段及目标脚本标识。发现旧调用名或无效的 `RequestType` 时，在查询结果中提示修正。
4. 在专用计算 App 逐笔调用该脚本，实际返回如下。普通接口脚本 `GuideFiveMean` 的独立请求仍返回 `mean=520` 和原有 B 版探针。

| 输入 | 脚本状态 | 实际关系型数据行 |
| --- | --- | --- |
| 480、500、520、540、560，质量均 192 | `ok` | `[{"mean":520}]` |
| 500、520、540、560、560，质量均 192 | `ok` | `[{"mean":536}]` |
| 仅四笔 | `need_five_samples` | `[]` |
| 第五笔质量为 0 | `bad_sample` | `[]` |

5. 使用本机同版 KF Node 安装中的 `kingclient/exe/lib/services/reportDataMng/index.js`，将当前账号从 Center 读回的数据集定义交给原生 `getReportData`。该模块通过真实 Center 的服务发现定位 3.32 上的计算 App，并读取实际 HTTP 回包。原配置只填 `samples` 时，计算返回 HTTP 400，报表成员为空。补齐请求格式后通用脚本返回单一数值对象；报表消费代码要求行数组。最终使用专用脚本返回 `type=relation` 及 `data=[{"mean":520}]`。18:22 原生报表模块实际输出 **`{"mean":[520]}`**。这次证据到达运行消费模块；已部署浏览器报表控件的 B4 视觉显示仍待验收。

该查询条件适合逐笔验算。该版本的报表消费模块直接解析已保存的条件，计算宿主按 `RequestID` 关联回包。多用户并发场景应由调用端逐次分配独立请求编号，需在实际部署版本另行验证。
